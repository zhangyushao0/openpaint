# Decisions

Only decisions that constrain the code now and are not self-evident, each stating today's design: date, decision, reason, consequences, at most 15 lines. A superseded decision moves to `docs/archive/` whole. "The previous project" is draweave (2026-07 to 2026-10), the predecessor this repository replaces.

## D01 2026-10-02 Stack: Rust 2024, wgpu, egui, one workspace
- Decision: core, rendering, application, storage and UI are all Rust; GPU through wgpu; UI through egui; Android is the only product host; the development machine runs a headless harness, never a desktop window (ARCHITECTURE). Reason: the previous project proved this stack on the target tablet (pressure, palm rejection, layer compositing, smudge). Consequences: renderer state never lives in egui's type map; egui appears only under `render/src/adapter/`.

## D10 2026-10-02 Errors are types; product crates have no cargo features
- Decision: `CoreError`, `AppError`, `PortError`, `RenderError`, `RuntimeError`; `Result<_, String>` only in JNI, system APIs and xtask. No `cfg(feature)` in product crates; diagnostics and automation live in separate crates assembled only by composition roots. Reason: the previous project's `String` errors and 379 `cfg` sites made four build combinations and hid diagnostics in product code. Consequences: `cargo repo-check` rejects `[features]` and `cfg(feature`; the platform layer turns typed errors into user-facing messages.

## D14 2026-10-02 External crates are pinned exactly in the workspace manifest
- Decision: every external crate is declared once in `[workspace.dependencies]` with an exact `=` version (wgpu 30.0.1, egui and egui-wgpu 0.36.2, fjall 3.1.11, image 0.25.10, png 0.18.1, moxcms 0.8.1, crc32fast 1.5.2, lz4_flex 0.13.1 and the rest); crates use `.workspace = true`. Gradle 8.13, the Android Gradle plugin 8.13.2 and Kotlin 2.2.21 are pinned in `apps/android`. Reason: wgpu and egui break APIs every release; a silent bump would change GPU behaviour and hashes without review. Consequences: wgpu, egui and egui-wgpu are upgraded together in one commit that reruns the GPU tests and re-records any moved hash with the reason.

## D18 2026-10-02 Only the stylus paints; touch is reserved for gestures
- Decision: a finger never draws. Pen contacts paint; touch drives the canvas (pan, pinch, rotate, two-finger undo, three-finger redo and the copy menu). The author's choice. Consequences: palm rejection treats touch as non-painting; a "finger paints" option would be a new decision.

## D19 2026-10-02 Scenario checkpoints compare canvas hashes; references stay untracked
- Decision: a checkpoint passes when the canvas readback (artwork pixels, no UI) hashes to the value in the scenario file; screenshots are for looking at, never compared; the diff reference is the last pass on this machine (`artifacts/scenarios/<name>/`, untracked). Reason: canvas pixels come from the renderer's own formulas, egui's text edges differ by backend. Consequences: a slice that changes pixels on purpose updates the hash in the same commit after looking at the PNG; UI changes are checked by screenshots and GPU tests on specific pixels.

## D40 2026-10-03 Paper-white line art: floating ink-outlined islands, the system's sans
- Decision: warm paper (250, 248, 244) islands and panels in a 1.25 pt ink outline (70, 67, 62), no shadows but the canvas's, the white canvas on a greyer desk (233, 230, 224), ink (38, 37, 35) text and icons, the active state an ink ring, pill or row outline in a deeper ink (22, 28, 44), never a filled block. Nothing spans the width: Gallery, Actions, Adjustments, Selection and Transform float top left, Brush, Smudge, Eraser, Layers and the colour top right, the side bar at the left edge; notices, bars and the zoom are pills in the 48-point top band; the canvas shows on the whole screen and fits under the band. Text is the system's sans (Roboto, Noto Sans CJK) at weight 400, 18-point body, found by the host in `/system/etc/fonts.xml`. Restraint: UI appears when needed; a hidden shortcut only duplicates a visible control.
- Reason: the author's chosen style (a calm sketchbook page, no dark chrome). Consequences: one theme in `ui/src/design/`; the pen's hover outline is drawn in the screen blit, black or white per pixel.

## D43 2026-10-03 A stroke drawn inside a selection stores its clip mask; fills are cut to it
- Decision: a selection is a `core::RegionMask` (pixel centres inside the closed polygon, even-odd; union, intersect, invert). A stroke begun while a selection exists keeps it as its clip, a hard edge, so it changes nothing outside; consecutive strokes share one mask in memory and after loading. A fill inside a selection stores the flood intersected with it; a drop outside is refused.
- Stored (D95): each stroke record ends with its clip (none, or rectangle and LEB128 runs).
- Reason: the clip must survive deselect and reopen; the bit mask is already the fill's form.
- Consequences: a clipped stroke stores its mask's runs again; edges are aliased (feathering needs a coverage mask, a format change); the screen marks the selection in the blit (outline just outside, still stripes over a light dim).

## D44 2026-10-03 One small motion system: five principles, four patterns, one spring
- Decision: motion only explains (where something comes from or goes, what changed, that input arrived), never on the drawing path, interruptible, critically damped, short; four patterns (emerge/retract, fade through, settle, acknowledge) built into the shared components on one spring in `ui/src/design/motion.rs` (open 0.38 s, close 0.25 s, a panel switch retracting the old panel in 0.12 s and growing the new one 0.05 s later). Panels share one ink outline with their island (an SDF chrome pass in `render/src/adapter`).
- Reason: the author's approved demo (`openpaint-lab/motion-demo` v3). Consequences: screens declare state and never animate by hand; a new pattern needs a decision; motion runs on elapsed time from the runtime's frame clock, which the harness holds fixed.

## D46 2026-10-03 Smudge is a stroke drawn as a residual `after = A x before + R`, after draweave's ADR-0049
- Decision: `StrokeTool::Smudge` (blend `Smudge`, or `SmudgeLocked` under Alpha Lock) is a stroke like any other. Its contacts walk the samples a quarter radius apart (at most one pixel; radius 0.5 to 300 px); each moves the share w = tip profile x opacity x pressure of the colour one step back: `F <- (1 - w) F(p) + w F(p - d)`, bilinear between pixel-centre nodes, transparency too, the layer's own pixels only. StreamLine follows strictly (no catch-up).
- Render (`render/src/smudge/`): each smudge is evaluated once, in layer order, into a residual of 32-pixel tiles (A and R per node) from the layer's pixels before it (its material); the raster core applies it as a pass from a copy (Alpha Lock keeps alpha, the clip limits writes); in progress = cold and committed = cold bit for bit. Residuals are derived caches in an arena, made again from the artwork when missing.
- Consequences: cost grows with the radius squared; a residual costs 20 bytes per pixel of its tiles; residuals are kept within a share of the GPU budget (D93).

## D48 2026-10-04 Scenarios name controls by their accessible label; device chores are xtask commands
- Decision: every shared component registers its label and rectangle in a per-pass `ControlMap` (always on); scenario steps, runtime tests and `device-input tap` name the control (`name #n` when shared), pixels only on the canvas, and pixels on a control fail the run with the name to write. Device work goes through `cargo device-*` (adb with explicit arguments, never a host shell; restore verified byte for byte).
- Reason: layout changes rewrote hard-coded taps in a dozen files; a hand-rolled device chore once wiped the author's library.
- Consequences: a new component registers its control; a label change is a scenario change; slider and wheel positions are offsets from the control's middle.

## D50 2026-10-04 Blend modes, Clipping Masks and groups: premultiplied formulas, chains as a unit, pass-through groups
- Decision: `core::BlendMode { Normal, Multiply, Screen, Overlay }`, composited premultiplied in sRGB-encoded values: `out = s(1 - da) + d(1 - sa) + B` with `B` = `s da`, `s d`, `s da + d sa - s d`, or Overlay's two cases (the W3C definitions without division, so zero source leaves a pixel exactly).
- Clipping (Photoshop's): a clipping layer's base is the nearest non-clipping layer below in the same group; a chain is one unit, each clip atop by its own mode and opacity, the chain composited by the base's opacity and mode; a hidden base hides its chain.
- Groups: one level, contiguous, a name, visibility and opacity, no mode; pass-through: its layers composite onto what lies under the group, and its end fades the result over that by the group's opacity. Moves step into and out of groups at their edges; Ungroup keeps a hidden group's layers hidden; collapsing is panel state.
- Rules: smudge, fill sampling and the transform's lift read the active layer alone; selection clips and Alpha Lock act inside the layer; fill and transform refuse a layer whose group is hidden; the eyedropper and export see the composite.
- Consequences: a group's own mode or isolation, nested groups and clipping across group edges would be new unit kinds.

## D51 2026-10-04 Layer masks: grey strokes and fills over white, an invert flag, applied before the layer's end
- Decision: `Layer::mask: Option<LayerMask { enabled, inverted, strokes, edits }>`, the paint's own stroke and edit machinery. `Artwork::on_mask` makes the active layer's mask the target (stored; never an off mask's). On a mask the brush lays its colour's grey (Rec. 601 luma), the eraser white, the smudge moves grey, fills store grey; Alpha Lock does not apply. Invert flips the flag and later marks store the opposite grey. Transform refuses on a mask; a whole-layer transform moves the paint only.
- Compositing: the mask's coverage `m` (nothing painted is 1; inverted `1 - m`) multiplies the layer before its opacity, mode, clipping and group; a base's mask shapes its chain, a clipping layer's only itself; a disabled mask contributes nothing.
- Stored (D95): the head's layer flags and counts; mask records under the layer id with bit 63 set (`mask_slot`).
- Consequences: masks on groups, applying a mask and moving it with its layer are later changes; the eraser reveals.

## D53 2026-10-04 Everything inside is sRGB; files are interpreted on the way in and declare sRGB on the way out (moxcms)
- Decision: artworks, the canvas and the screen are sRGB-encoded; colour management happens only in `store/src/colour.rs`. In: a PNG `iCCP` or JPEG APP2 RGB profile converts the decoded RGBA8 into sRGB (perceptual: clipping per channel for matrix profiles) before premultiplying, for inserted and reference pictures; a profile mapping 1,536 probe colours to themselves counts as sRGB and keeps every byte; no, unreadable, grey or CMYK profiles: the values are taken as sRGB (logged). Out: PNG and JPEG exports embed one fixed sRGB profile (`store/assets/srgb.icc`, 612 bytes). The surface is declared `SurfaceColorSpace::Srgb`.
- Reason: phones write Display P3; read as sRGB numbers they look washed out.
- Consequences: a P3 working space or deeper pixels are format changes for the author; 16-bit PNGs are reduced to 8 bits before converting.

## D55 2026-10-04 The renderer at an output scale; export at 1x, 2x and 4x in bands
- Decision: a target lies at an `Output` (`render/src/output.rs`): 1, 2 or 4 output pixels per canvas pixel and its origin. Every unit is drawn at the output pixel's centre mapped back to canvas pixels: a hard stroke edge antialiases over one output pixel, a soft one keeps its canvas width; the paper's moment level drops one per doubling; grain, clips and fill masks are read nearest on the canvas grid; patches, filter results and smudge residuals bilinear.
- Export (`Core::export_bands`): pieces at most 4096 wide, bands of 512 output rows, each read back and streamed: PNG through png's stream writer (sRGB profile, D53); JPEG collects its rows, so it is offered up to 2x only (`ExportScale::fits`). The scale is the Share section's choice for the app's run.
- Reason: strokes are the truth (author, 2026-10-04): evaluated at the file's resolution they are sharp for free, with one scale instead of a second renderer.
- Consequences: the encoded file is held in memory for the one `ImageSink::write`; PNG encoding is most of a 4x export.

## D56 2026-10-04 A fill's edge is derived from its mask at every scale
- Decision: a fill is a bit mask over its rectangle, a colour, the Alpha Lock it was made under and its place among the target's strokes; its edge is derived, never stored. The mask's signed distance field at each pixel centre, averaged along the edge (triangle weights over 5 px) where the edge points within 6 px lie along a line (RMS at most 0.45 px), at most 0.5 px from the field; bilinear between centres its zero line is the edge, a pixel's coverage its share inside (4 x 4 subsamples): antialiased over one output pixel at every scale; corners, tight curves, dots and noise keep the field. Past the canvas the mask continues as its edge pixels.
- Where: `render/src/fill_edge.rs` derives the values when a scene first draws the mask; the next scene on the same target reuses them; `shaders/fill_edge.wgsl` reads them.
- Consequences: deriving costs about 0.9 µs per edge centre on the thread building the scene (the main thread for a fill preview); a transform's lift and selection clips stay hard.

## D57 2026-10-04 A transform is a record drawn by mapping back; the lifted patch is only the drag's preview
- Decision: a transform is `TransformEdit { after, lift: Option<RegionMask>, patch: None, placement }` (`Artwork::place_region`): what moved (a selection or the whole layer) and where, no pixels. The raster core draws the content before it on its layer in the record's frame (each pixel's centre mapped back; a whole layer's content cut to the canvas; a selection's both where it stays, its lift cleared, and moved on a level target, cut to the mask); grain, paper, clips, fill edges and residuals are read at the mapped point, edges one output pixel wide at the placement's scale. An inserted picture is a patch (D67).
- Interaction: corners scale evenly, the stem's handle turns, the pen inside moves, fingers move, pinch and twist; Flip, Rotate 45°, Reset; steps with their own undo; another tool commits; a selection transform deselects. While the hand drags the preview places the lifted patch; once it lifts (and after every tap, undo and redo) the preview is the record: settled equals committed.
- Stored (D95): edit kind 2, its patch optional.
- Reason: strokes are the truth (D55): scaled content stays sharp and repeated transforms never soften.
- Consequences: a step costs about 350 bytes; a selection cut keeps the mask's hard pixel edge; more than `MOVE_DEPTH` 16 levels of moved or merged content at one place refuse to draw.

## D59 2026-10-05 Adjustments are operation records; blur and sharpen read a derived canvas-resolution boundary
- Decision: an applied adjustment is `RegionEdit::Adjust(AdjustEdit { after, clip, adjustment, inverted })` among the target's strokes: `Hsb` (hue turns by `hue - 0.5` of a turn, saturation scales from the Rec. 601 luma by `2 s`, brightness to black below 0.5 and white above; 0.5 changes nothing), `Curves` (four monotone `ToneCurve`s of at most 16 points, applied through 8-bit tables read between entries, D70), `Blur { radius }` (standard deviation up to 32 canvas pixels; from 4 px on reduced means within 3 levels of the exact Gaussian) or `Sharpen { amount }` (`c + 2 amount (c - G1(c))`). On a mask it changes the grey shown.
- Filters: the layer's content before the record is drawn at 1x into a material, filtered by a separable kernel (`filter/kernels.rs`, explicit 8-bit rounding) into an arena block, which replaces the layer inside the clip, bilinear at higher scales. Results are keyed by what they depend on and dropped with the arena's other blocks.
- Interaction (Procreate's Layer mode): the wand's menu; a panel of values, Reset, Cancel, Apply; every value previews as the commit would show it; Apply is one step (nothing when nothing changes); any other edit, tool or leaving applies it; hidden and locked layers refuse (`LayerRefusal`).
- Reason: truth is operation records; pixels are derived, discardable caches (author, 2026-10-04).
- Consequences: no per-layer pyramids or disk caches of filters; filters ignore Alpha Lock and content brought in from beyond the canvas.

## D62 2026-10-05 An OpenPaint file (`.openpaint`) is the artwork's own library records with a check sum; it opens as a new artwork
- Decision: the file is the magic `OpenPaint\0`, the format (u32, D95), the title, every record of the project as the library stores it (keys without the project id, length-prefixed, in key order; the head without its save id), then the CRC-32 of all before it (`store/src/artwork_file.rs`). No container, no serialization crate; the toolbox, history and versions are not in it.
- Opening: no magic is `NotArtworkFile`, another format `OtherFormat` (checked before the sum), a wrong sum or a record that does not decode or breaks the artwork's rules `Corrupt`/`Invalid`; the artwork is checked whole before the library writes it under a new id, listed first.
- Android: saved through ACTION_CREATE_DOCUMENT as application/octet-stream (the name keeps its extension), opened through ACTION_OPEN_DOCUMENT on `*/*`; no intent filter.
- Reason: the records already are a lossless form with a frozen sample; a second encoding would be a second format to keep equal.
- Consequences: a format change changes files too; a file costs the records plus the thumbnail.

## D64 2026-10-05 The screen's canvas and view tiers hold ten-bit codes that read back as their 8-bit values
- Decision: where the device writes Rgb10a2Unorm (the adapter's format features) the screen's canvas target, the view tiers' atlases and the harness's offscreen screen are Rgb10a2Unorm and the surface prefers Rgb10a2Unorm in sRGB, which the tablet's display processor composites as it is; elsewhere all stays 8-bit. Such a target is written `coded` (`raster_composite.wgsl`): the ten-bit code nearest the composite among those whose nearest 8-bit value is the one an 8-bit target stores, so `readback::eight_bits` gives exactly the 8-bit bytes. Exports, picks, layer and mask samples and materials are 8-bit; display targets are opaque.
- Reason: one display precision at the same bytes per pixel, every hash unchanged by construction.
- Consequences: stored content stays 8-bit (patches, pictures, filter blocks); `cargo device-input gradient on|off` (debug builds) shows an 8-bit and a ten-bit ramp.

## D66 2026-10-05 Layer panel with Merge Down: the upper layer becomes a nested record in the lower one, the look unchanged
- Panel: rows top first, each with a derived picture of its layer alone (drawn at canvas size, box means on the GPU, coverage at its cube root, on the `openpaint-pictures` worker while the panel is open, never mid-stroke, never stored); a row held still 0.4 s moves to the nearest of `layer_places` (one `Move`); Duplicate (new ids throughout) and Rename are one step each.
- Merge Down: `LayerCommand::MergeDown` removes the upper layer and appends `RegionEdit::Nested(NestedEdit { after, layer: Arc<NestedLayer { id, opacity, blend, clipped, strokes, edits, mask } }>)` to the lower one, which keeps its id, name, place and switches. Nothing is baked; records nest up to `MAX_NESTING` 8.
- Drawing: the record's content is a level target of its own laid onto the layer so far by the same expressions a layer's end uses (atop when it clipped, else by its mode); later edits of the merged layer act on all of it.
- Allowed only where the composite provably stays (`Artwork::mergeable`, else the reason at the row's end): a clip onto its base at any mode; otherwise both Normal, Multiply or Screen with the same clipping and nobody clipping to the upper one (the lower layer's enabled mask and opacity moving into a record of their own). Hidden or locked layers, the bottom of a stack or group and more than 8 deep refuse.
- Stored (D95): edit kind 4 (`store/src/nested.rs`), its content under its own id.
- Reason: strokes stay the truth and the picture must not change (the author's option (a)). Consequences: a Multiply or Overlay layer that does not clip cannot merge into a Normal one; over-merges may move rare pixels one 8-bit level.

## D67 2026-10-05 Copy and paste are records; an inserted picture or a pasted copy is a transform draft on a new layer
- Insert: Insert image… decodes on the transfer worker (EXIF upright, premultiplied, colour per D53), reduces a picture larger than the canvas once (triangle filter), centres it on a new layer "Inserted image" above the active one framed as a transform draft whose patch is the picture; the commit (even unmoved) is one step with the layer; undo at its first step drops both; stored as a transform with its patch.
- Copy: `Artwork::copied(all, clip)`: Copy, the active paint as one nested record (D66) at full opacity by Normal with its enabled mask; Copy All, one record per visible clipping chain, a faded group a record by its opacity; inside a selection the pixels outside cleared (`RegionEdit::Clear`, edit kind 1). `paste` renumbers every record; `cut` clears the selection or empties the paint.
- Paste: a new layer "Pasted layer" framed by the Transform tool as an insert is; committed unmoved it is the layer alone, moved a record; the commit deselects. The clipboard is the runtime's for the app's run, not the system's, onto a canvas of the copy's size only.
- Menu: three fingers swiped down on open canvas (their middle at least 48 pt down within 30 degrees of vertical, by 0.8 s) or Actions > Copy & Paste open a pill of Cut, Copy, Copy All, Duplicate, Cut & Paste, Paste; a three-finger tap stays redo.
- Reason: strokes stay the truth; one nested record kind serves Merge Down and copies. Consequences: Copy All composites a faded group as if isolated; a copy nesting more than 8 deep is refused.

## D69 2026-10-06 Session tool state beside the artwork: the selection and the Drawing Guide; QuickShape and symmetry change only the strokes stored
- Selection: `app::Selection` holds the tool, the shape and its steps (closing a shape adds it; Invert and Deselect are steps); while the tool is on, undo and redo walk these steps, off it the artwork's history; never stored. The Drawing Guide (on, symmetry, centre) is session state; every artwork opens with it off.
- QuickShape: the pen resting within 5 points for 0.5 s (`StrokeIntent::Hold` each frame by the input clock) snaps the stroke to what `quickshape_fit::recognise` finds (line, arc, ellipse or circle, polyline) by `StrokeSession::reshape`: samples along the exact shape carrying the drawn stroke's pressure, tilt and time at the same share of its length. Edit shape's handles replace the stroke and its copies with `History::amend`: drawing, snapping and editing are one step.
- Symmetry (Procreate's mirrored default): each copy is a stroke record of its own; while drawing the session shows the base with the copies under the stroke; at the lift the copies, then the stroke, are one step. Fills, selections, transforms and adjustments are not mirrored.
- Reason: snapped shapes and copies are ordinary records, sharp at every scale; one in-progress stroke in the renderer stays.
- Consequences: each frame of a mirrored stroke and each handle move rebuild the scene and draw the copies whole; no second-finger constraint while palm rejection takes touches under the pen.

## D70 2026-10-09 Tools, colours and the pen's three side buttons; curve tables read between entries
- Tools and colour: the eraser and the smudge are tools beside the brush with the same recipes, each its own brush and per-brush size and opacity; the eraser takes coverage x opacity away; Alpha Lock is a layer property a stroke captures when it begins (paints atop; the eraser there is refused); colours are 8-bit, joining the eight recent ones when they settle; one palette of up to 24 swatches; the hex field takes `#RRGGBB` on Enter; none of it is a history step.
- Pen buttons: Android's button state on every pen event gives the side buttons from the tip outwards as `BUTTON_STYLUS_PRIMARY`, `BUTTON_STYLUS_SECONDARY` and `BUTTON_TERTIARY` (no key events from the author's pen); each does Nothing, Eraser, Eyedropper, Undo, Redo or Switch tool (Eraser, Eyedropper, Undo at first). `app::ButtonTracker` places intents around each batch's contacts: a held tool before a contact touches down (the eraser end holds the eraser while in range; else the first button's before the second's before the third's), its release after the lift; Undo, Redo and Switch tool fire once per press, on the glass at the lift. Held tools are never stored; the map is, with the toolbox.
- Curves: 256 8-bit entries per channel, read linearly between the two around `colour x 255`, so a gradient through a steep curve steps by one level (one code at ten bits).
- Reason: a pressed button is state on Android, so acting at contact boundaries never cuts a stroke or a pick in two. Consequences: a pen sending its buttons only as key events does nothing (logged).

## D71 2026-10-09 Strokes follow a centripetal Catmull-Rom curve through their knots, their radius scaled by tilt and tapered at the ends
- Curve: a stroke is drawn along the centripetal Catmull-Rom spline (Barry and Goldman's tangents, a mirrored knot past either end) through every sample but those Android makes up (on the chord or the line past the last knots within 0.02 px, the pressure before it); each span is a cubic Bézier with its flatness and bend (`curve.rs`), flattened into at most 128 capsules within 1/16 output pixel at the output's footprint; radius, flow and paper contact change evenly along it; two-sample and straight strokes are their segments exactly. StreamLine is draweave's leash in the app's stroke intent (positions only); the stored stroke is the smoothed path.
- Tilt and taper: size and opacity dynamics are pressure x speed x tilt (degrees from upright 0 to 90; a size's factors up to 4, `Curve::gain`); a flat curve multiplies by exactly 1. The taper (start and end in diameters, the tip's share) multiplies each knot's radius by the smaller of two smoothsteps along the chords; a lone knot is never tapered; the pen's outline shows the brush untapered.
- In progress and the lift: a stroke being drawn has no end taper (its end blunt); the lift draws the spans within the end length again, so every frame equals the stroke so far cold and the frame after the lift the committed stroke. A smudge takes the start taper only; mirrored copies are committed strokes and show their end taper.
- Reason: strokes are the truth and sharp at every scale; per-knot factors need no per-scale state. Consequences: fast strokes taper in straight steps between knots; a slow hard turn between dense samples rounds over about one sample spacing.

## D74 2026-10-09 Brush recipes are fixed typed stages drawn per pixel from the path; the user edits, copies and arranges them in sets, stored with the toolbox
- Recipes: a built-in is a TOML file of fixed typed stages (`app/src/recipe.rs`, unknown keys refused) read into `core::BrushRecipe`: softness, size and opacity dynamics (D71), grain, deposit (D38), taper (D71), shape; no node graph, no shader plugins; a new stage is a field and a format change; a stroke keeps its recipe's snapshot; brush edits are no history steps.
- Shape (after Ciallo, Shen 2024): spacing 0 is the continuous capsule; else stamp n lies n x spacing x size along the chords and belongs to the one span whose length range holds it, so in progress = cold, bands = one piece, tiers = export. A stamp is a disc, square, ellipse or texture, turned fixed, along the direction or by the azimuth plus an angle, scattered and jittered by `core::jitter(seed, n)` (PCG, the same in WGSL); covering strokes keep the largest stamp, accumulating ones sum density. At most `MAX_STAMPS` 48 per pixel per span; a recipe that could need more is refused.
- Textures: `cargo shape-assets` writes `render/assets/shape-{chalk,grainy,splatter,rough-square}.bin` (256 x 256 signed distances; SHA-256 chalk ab0ee36fa5ada4fb, grainy dda8ac4f6a152586, splatter d24f0af92209740c, rough-square 304dfa261322be3f; an xtask test compares them). A released texture never changes.
- Seeds: every stroke stores a u32 seed from a clock-seeded SplitMix64 (the harness fixes 0x5EED0045); mirrored copies and a reshape keep their stroke's.
- Editor: the chosen brush's row tapped again turns the picker into its editor in place; each control's range comes from the recipe (`app/src/brush_fit.rs`), so the engine never refuses a change; Duplicate (`copy-<n>`), Reset (built-ins), Delete (copies). The toolbox record stores built-ins by key and every other brush whole; a stored brush the engine refuses falls back to its built-in.
- Sets: every brush lies in exactly one of Sketching, Inking, Painting and Texture in the hand's order (`ui/src/row_drag.rs` serves sets and layers), a brush in no stored set where a first start puts it; Recent lists the brushes of the last six committed strokes; a picker opens on the chosen brush's set.
- A later built-in (Hard Paint, S104, 2026-11-05) reaches every kept toolbox by the record's rules, no upgrade step: a missing built-in returns where its file's order puts it, a brush in no stored set goes to its home after the nearest one before it; a set arranged by hand keeps its order. Painting: Hard Paint, Hard Round, Soft Brush, Textured Round (V大's four), Flat, Opaque Paint; Texture: Speckle.
- Consequences: stamps follow the chords (up to 1/16 px off a curve) and space by size, not pressure; no import or export, no renamed or added sets.

## D77 2026-10-12 The library: records per change, every write one atomic batch; the stroke being drawn committed when the app is interrupted
- Records: one fjall database, keyspace `library` (format, ids, change clock, `last`, catalogue and version entries, the toolbox) and `projects` (per project a head, one record per stroke and per edit, a thumbnail, versions; big-endian keys, fixed-width little-endian values through `store/src/codec.rs`). A save writes the head plus the records after each layer's common prefix with what the library wrote last. The toolbox is stored apart and reads as its defaults when it cannot be decoded.
- Atomic writes (`batch.rs`): every call that writes is one `Batch` over both keyspaces, committed with `SyncData`; a journal cut anywhere inside it is dropped at the next open. Leaving is four calls, each whole: the save, the thumbnail, the kept version, closing.
- Interrupted mid-stroke: `Runtime::leave` (`onPause`) and `detach` commit the stroke being drawn as its lift would and hand it to the store.

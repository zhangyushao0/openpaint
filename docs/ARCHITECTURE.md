# Architecture

OpenPaint is an Android-first, stylus-first 2D painting app whose goal is to take an illustration from sketch to delivery on one tablet. Android is the only product host. On the development machine a headless harness renders offscreen, replays recorded input and runs scenarios; there is no desktop window and no desktop product.

This page is the design contract: how modules are cut, which way dependencies point, what the core types look like, how threads and errors are handled. When code and this page disagree, change the code or change this page and record a decision; never keep both. Type sketches land slice by slice; once landed, code is the truth and this page follows.

## 1. Principles

1. One concept has one definition and one owner, and the owner is a module, not just a crate. Mutable/immutable, intent/command and persistent/session forms are never kept twice.
2. The artwork is an immutable value. An edit produces a new version, history stores versions, undo switches versions.
3. Product crates have no `cfg(feature)`. Diagnostics, experiments and automation probes live in separate crates and are assembled only by composition roots.
4. The renderer depends on core only. GPU state belongs to the renderer's own `Core`, never to the UI framework; "evaluate a batch of regions into a target" has exactly one entry point: the raster core, for every scene and every product path (D92, D93: the only render core); the GPU protocol is defined once in Rust, injected into WGSL and proven by layout tests.
5. Pay per change: saving, history budgets, asset reclamation and projections touch only the data this change involves; the UI thread never does work proportional to artwork size.
6. Errors are types. `String` errors are allowed only in JNI, at system boundaries and in xtask output.
7. One user action has one product path: no double writes, no simple/advanced variants, no silent fallbacks, no modules or abstractions reserved for features not yet accepted.
8. Files at most 400 lines, functions at most 60 lines, tool-enforced; `lib.rs` holds only `mod` and `pub use`.

## 2. Crate map

| crate | Responsibility | May depend on | Must not contain |
| --- | --- | --- | --- |
| `openpaint-core` | artwork semantics: layers, strokes, commands, validation, brush recipe data | nothing | GPU, UI, file system, threads, clocks |
| `openpaint-raster` | pure pixel geometry on the CPU: the fill's connected region, a transform's lifted pixels | core | GPU, UI, file system, threads |
| `openpaint-app` | application flow: intents, session, history, workspace, editor state, capability ports (traits) | core | GPU, UI, file system |
| `openpaint-store` | local artwork library: the storage format (format 1), OpenPaint files and kept versions, image files; implements the app ports | core, app | GPU, UI |
| `openpaint-render` | derived rendering: wgpu pipelines, the raster core, region drawing; export, pick and preview consumers | core | file system; `egui` only under `src/adapter/` |
| `openpaint-ui` | shared interface: egui panels, input ownership, canvas arbitration; reads app projections, emits intents | core, app, render | direct wgpu, file system |
| `openpaint-runtime` | frame loop, input normalisation, bounded workers, lifecycle draining, startup | core, app, store, render, ui | JNI |
| `openpaint-devtools` | diagnostics and automation: scenario files, the scenario runner, checkpoint diffs; later observers and statistics | product crates (uses runtime, render) | file system, product rules; never a dependency of a product crate |
| `openpaint-harness` | development harness: offscreen rendering, recorded-input replay, `scenario` command, PNG and hash output; never shipped | all, devtools | windowing, mouse input, product rules |
| `openpaint-android` | the only product composition root: activity lifecycle, Surface, system pickers, JNI | all | product rules |
| `xtask` | repository tooling: `cargo gate`, `cargo repo-check`, the Android build, device chores over adb (`device/`) | nothing | product code |

Dependencies only point down (`A <- B` means B depends on A):

```text
core <- app <- store
core <- app <- ui <- runtime <- {harness, android}
core <- render <- ui
core <- raster <- runtime
store, render <- runtime
runtime <- devtools <- harness
```

A new crate is registered in `LAYERS` in `xtask/src/check/rules.rs` first (raster since S15).

The app's version is `[workspace.package] version` in the root manifest: xtask's Android build hands it to Gradle with the store's `FORMAT` as build metadata (`versionName` `0.8.0+format1`, `versionCode` 800; `xtask/src/version.rs`, D79), and the runtime shows the same two as Actions' last line (`host::version_line`: "OpenPaint 0.8.0 · format 1").

## 3. Core types (target shape)

### core

```rust
pub struct Artwork(Arc<ArtworkState>);           // snapshot as value: clone is O(1), history stores versions
struct ArtworkState { canvas: CanvasSize, background: Background, layers: Vec<Layer>,
                      groups: Vec<LayerGroup>, active: LayerId, ids: IdCounters }
pub struct Layer { id: LayerId, name: Name<80>, props: LayerProps, strokes: StrokeList,
                   image: Option<LayerImage>, edits: Arc<[RegionEdit]> }
pub struct LayerProps { visible: bool, opacity: f32, locked: bool, alpha_locked: bool,
                        clipping: bool, blend: BlendMode, group: Option<GroupId> }
pub struct StrokeList { chunks: Arc<[Arc<[Stroke]>]> }         // appending copies only the last chunk (<= 256 strokes)
pub struct Stroke { id: StrokeId, tool: StrokeTool, style: StrokeStyle,
                    samples: Arc<[StrokeSample]>, constraints: StrokeConstraints }
pub struct StrokeSample { position: CanvasPoint, pressure: f32, tilt: f32, azimuth: f32, time_ms: u32 }  // time from stroke start
pub struct StrokeStyle { recipe: BrushRecipe, size: f32, opacity: f32, color: Color }
pub enum ArtworkCommand { Layer(LayerCommand), Group(GroupCommand),
                          Reference(ReferenceCommand), Background(BackgroundCommand) }
pub struct Applied { pub artwork: Artwork, pub change: Change }  // Change: None | ActiveLayer | Reference | Content
impl Artwork {
    pub fn apply(&self, cmd: ArtworkCommand) -> Result<Applied, CoreError>;     // one editable_layer() precheck
    pub fn edit_region(&self, edit: RegionEdit) -> Result<Applied, CoreError>;   // commits of selection, fill, transform
    pub fn begin_stroke(&self, style: StrokeStyle, first: StrokeSample) -> Result<StrokeSession, CoreError>;  // on the active layer
    pub fn from_storage(parts: ArtworkParts) -> Result<Self, CoreError>;        // the single full-validation entry
    pub fn to_parts(&self) -> ArtworkParts;                                     // plain data for the store
}
pub struct StrokeSession { base: Artwork, active: ActiveStroke }   // extend / finish / cancel; the active stroke is not in a layer
```

No public mutable setters. Layers come only from `from_storage` or commands; single values (`Stroke`, `LayerGroup`, `LayerImage`) validate themselves on construction. Landed in S2: canvas, layers, active, ids; `LayerProps { visible, opacity, locked }`; `StrokeStyle` without a recipe; `ArtworkCommand::Layer` only; `Change` without `Reference`. `LayerCommand` is `Create` (above the active layer, becomes active), `Delete`, `Reorder`, `Select`, `Rename`, `SetVisible`, `SetOpacity`, `SetLocked`; a command that changes nothing returns `Change::None` and the same version. Lock blocks content (strokes), not properties or position. Ids are never reused; limits (`MAX_LAYERS`, `MAX_STROKE_SAMPLES`, `MAX_CANVAS_SIDE`, ...) are public constants. Landed in S11 (D27): `BrushRecipe { softness, size: Dynamics, opacity: Dynamics, grain: Grain }`, `Dynamics { pressure: Curve, speed: Curve }`, `plain()`; `StrokeStyle` holds an `Arc<BrushRecipe>` and is `Clone`, not `Copy`; `RecipeParts` in `StrokeParts`. Landed in S12 (D30): `StrokeTool { Paint, Erase }` in `StrokeStyle` (`with_tool`); `LayerProps::alpha_locked` and `LayerCommand::SetAlphaLocked`; a stroke captures the layer's Alpha Lock when it begins, so `Stroke`/`ActiveStroke::blend()` is a `StrokeBlend { Over, Atop, Erase }` (stored in `StrokeParts::blend`); the eraser on an alpha-locked layer is `CoreError::AlphaLocked`. There is no separate `constraints` field yet. Landed in S15 (D36): `Layer::edits() -> &[RegionEdit]` (`after`, `mask: RegionMask`, `color`, `alpha_locked`); `RegionMask` (`from_pixels`, `from_runs`, `runs`, bit-packed rows in its rectangle); `Artwork::fill_region(mask, color)` on the active layer instead of a generic `edit_region`; `FillParts` in `LayerParts::fills`; no `LayerImage` yet. Landed in S16 (D38, D39): `deposit.rs`: `BrushRecipe::deposit() -> &Deposit { Cover, Accumulate(Accumulation { tip: Tip { Flat, Bell }, flow, max_density, paper: Option<Paper { texture: PaperTexture::Sketch, contact: Curve, scale, depth, dust }> }) }`, set by `with_deposit` (no softness with it); `RecipeParts::deposit: Option<AccumulationParts>`; `StrokeSession::revise(from, samples)` replaces a stroke's end (never its first sample). Landed in S18 (D43): `mask_ops.rs`: `RegionMask::{polygon, union, intersect, inverted, whole}`; `StrokeSession::clipped(mask)`, `Stroke::clip`, `ActiveStroke::clip`; `MaskParts` in `StrokeParts::clip`. Landed in S20 (D45): `RegionEdit` is `Fill(FillEdit)` or `Transform(TransformEdit { after, lift, patch, placement })` with `after()`, `fill()`, `transform()`, `same()`; `transform.rs`: `Placement` (affine, `around`, `moved`, `then`, `apply`, `inverse_rows`, `MAX_SCALE`), `Patch` (premultiplied RGBA8 in a rectangle), `Artwork::transform_region(lift, patch, placement)` on the active layer; `LayerParts::edits: Vec<EditParts { Fill, Transform(TransformParts) }>`. Landed in S21 (D46): `StrokeTool::Smudge`, `StrokeBlend::{Smudge, SmudgeLocked}` (a smudge on an alpha-locked layer is allowed and keeps alpha). Landed in S23 (D50): `BlendMode` (`blend.rs`); `LayerProps::{clipping, blend, group}`; `LayerGroup { id: GroupId, name, visible, opacity }` in `ArtworkState::groups` (`group.rs`: `check_groups`, `members`, `prune`; group ids from the layer counter); `Artwork::{groups, group, shown, clips_at}`; `ArtworkCommand::Group(GroupCommand { Create { layer }, New, Ungroup, SetVisible, SetOpacity })` in `group_command.rs`; `LayerCommand::{Raise, Lower, SetClipping, SetBlend}` (moves in `layer_moves.rs`; `Reorder` never splits a group); `CoreError::{UnknownGroup, GroupLayered}`; `GroupParts`, `ArtworkParts::groups`. Landed in S24 (D51): `mask.rs`: `Layer::mask() -> Option<&LayerMask { enabled, inverted, strokes, edits }>`, `grey_of`; `ArtworkState::on_mask` (`Artwork::on_mask`, cleared by `activate`), `ArtworkCommand::Mask(MaskCommand { Add, Select, SetEnabled, Invert, Clear, Delete })` in `mask_command.rs`; `Artwork::target()` routes `begin_stroke` and `fill_region` to the mask (`ActiveStroke::on_mask`); `CoreError::{NoMask, MaskOff, OnMask}`; `LayerMaskParts`, `ArtworkParts::on_mask`. Landed in S28 (D54): `adjust.rs`: `Adjustment { Hsb(Hsb), Curves(Curves) }`, `AdjustmentKind`, `ToneChannel`, `RegionEdit::Adjust(AdjustEdit { after, clip, adjustment, inverted })` (`RegionEdit::adjust()`), `Artwork::adjust_region(clip, adjustment)` on the target (paint or mask), `AdjustParts`/`AdjustmentParts` in `EditParts::Adjust`; `tone.rs`: `ToneCurve` (2 to `MAX_TONE_POINTS` points, monotone cubic `value`, 8-bit `lut`, `with_point`, `moved`). Landed in S31 (D57): `TransformEdit::patch() -> Option<&Patch>` (`None`: a record), `Artwork::place_region(lift, placement)` beside `transform_region` (pixels: inserted pictures, the drag's preview); `TransformParts::patch: Option<PatchParts>`. Landed in S33 (D59): `filter.rs`: `Blur { radius }` (standard deviation in canvas pixels, `MAX_RADIUS` 32), `Sharpen { amount }` (`RADIUS` 1, `STRENGTH` 2); `Adjustment::{Blur, Sharpen}`, `AdjustmentKind::{GaussianBlur, Sharpen}`, `AdjustmentParts::{Blur, Sharpen}`: filters are adjustment records like the others. Landed in S38 (D65): `LayerCommand::{Move { layer, by }, Duplicate}` (a copy's strokes renumbered, `Layer::duplicate`); `layer_moves.rs`: one step's rule `stepped` over the layers' groups, shared by `Raise`, `Lower`, `Move` and the public `layer_places` (`LayerPlace { by, index, group }`); `Layer::same_paint`, `LayerMask::same_grey`, `StrokeList::same` (pointer equality). Landed in S39 (D66): `nested.rs`: `RegionEdit::Nested(NestedEdit { after, layer: Arc<NestedLayer { id, opacity, blend, clipped, strokes, edits, mask } }>)` (`depth`, `MAX_NESTING` 8, renumbered by `Layer::duplicate`); `merge.rs`: `LayerCommand::MergeDown`, `Artwork::mergeable -> Result<(), Unmergeable { NothingBelow, Hidden, Locked, Modes, BelowClips, ClippedTo, TooDeep }>`, `CoreError::Unmergeable`; a merge removes the upper layer and appends its record to the lower one (whose enabled mask, and over an opacity below 1, move into a record of their own); `NestedParts`, `EditParts::Nested`; `from_storage` claims a record's id as a layer id and refuses a disabled nested mask, records in masks and more than 8 deep. Landed in S40 (D67): `clear.rs`: `RegionEdit::Clear(ClearEdit { after, mask })` (pixels made transparent), `Artwork::cut(clip)` (a clear on the active paint, or the paint emptied); `copy.rs`: `Copied { canvas, edits }`, `Artwork::{copied(all, clip), copyable(all), paste(&Copied)}` (Copy: the active paint as one `NestedLayer` at 1 by Normal with its enabled mask; Copy All: a record per visible clipping chain, a faded group a record by its opacity; a clip adds the inverted selection as a clear; `paste` renumbers through `NestedLayer::renumbered`), `CoreError::{NothingToCopy, TooDeep}`; `ClearParts`, `EditParts::Clear`; recipe parts moved to `parts_recipe.rs`. Landed in S42 (D69): `StrokeSession::reshape` replaces every sample, the first too (a stroke snapped to a shape). Landed in S44 (D71): `Dynamics { pressure, speed, tilt }` (`with_tilt`, `at(pressure, speed, tilt)`), `Curve::gain`, `MAX_TILT`, `MAX_GAIN`; `taper.rs`: `Taper { start, end, tip }` (`NONE`, `factor`, `MAX_TAPER`), `BrushRecipe::{with_taper, taper}`; `RecipeParts::{size_tilt, opacity_tilt, taper}`. Since S72 `LayerCommand::{Reorder, Raise, Lower}` are gone: `Move { layer, by }` is the one move, its single steps (`stepped`) the ones `layer_places` lists.

### app

```rust

pub enum Intent { Stroke(StrokeIntent), Artwork(ArtworkCommand), Tool(ToolIntent), View(ViewIntent),
                  Selection(SelectionIntent), Fill(FillIntent), Transform(TransformIntent),
                  Brush(BrushIntent), History(HistoryIntent) }
pub enum AppError { Core(CoreError), Busy(BusyReason), Brush(BrushLibraryError), Port(PortError) }
pub trait ProjectStore { /* list, create, load, save, rename, duplicate, delete */ }
pub trait AssetStore   { /* import_image, load_image */ }

Each intent family is one module holding its intents, handlers, projection and tests. ## 4. Input

Hosts deliver platform events as `runtime::MotionBatch` (phase, buttons, pointers with tool kind and batched samples: position, pressure, tilt, orientation, time); the Android host decodes `MotionEvent` arrays into it in `apps/android/src/motion.rs`. The Android host and the harness feed one normaliser (`runtime/src/normalise.rs`): `MotionBatch` -> `app::InputBatch` (per contact: id, device, phase, samples with position, pressure, tilt, azimuth, timestamp; ranges clamped, times monotonic per contact). egui receives its pointer events from these batches on every platform; no windowing library sits in between. The UI's canvas input (`ui/src/canvas_input.rs`) owns each pen contact that touches down on the canvas itself, outside every control, and hands it to the session as `Intent::Stroke` with its samples mapped through the view into canvas pixels (while the eyedropper is on, any contact, picking). It also follows where the pen hovers over open canvas (for the brush outline) and which fingers are down. Every finger contact goes to `app::Gestures` with whether it touched down on open canvas; what fingers mean (navigation, quick pinch, taps, the three-finger swipe down: `gestures/swipe.rs`, S40) is decided there, in points, not in the UI's widgets and not in the platform layer; a control that takes a contact resets the trackers. StreamLine lives in the app's stroke intent (S16, D60): the stored samples are the smoothed path; the renderer draws the curve through them (S34). Palm rejection is an app rule too, `app::PalmRejection`, which the runtime applies to every normalised batch before egui or the canvas frame sees it, because a palm must not press buttons either: while a pen contact is down, touches are palms until they lift; a pen landing cancels the touches already down. Platform cancels (`ACTION_CANCEL`, `FLAG_CANCELED` on an up) arrive as `Cancel`; egui gets a cancel as a release far off screen, never a click. The stroke intent drops the zero-pressure lift sample Android reports as the pen leaves the glass. The pen's three side buttons (S41, S43, D70: from the tip outwards `BUTTON_STYLUS_PRIMARY`, `BUTTON_STYLUS_SECONDARY`, `BUTTON_TERTIARY`) are read from the button state of every pen event (hover, touch, `ACTION_BUTTON_PRESS`/`RELEASE` as a batch of no contacts) into `InputBatch::pen`; the normaliser logs each change; `CanvasInput` hands each batch to `app::ButtonTracker` before and after its contacts, so a held tool is in place before a contact touches down and comes back after the lift; finger batches carry no buttons. Stylus key events are only logged by the host. The in-progress stroke travels to the renderer as a separate item and never enters the artwork. Keyboard text reaches egui as IME and key events through `Runtime::text`; the host shows the soft keyboard while `keyboard_wanted` (D26). The back button goes to `Runtime::back`, which the shell answers (canvas to gallery, closing a dialog) or leaves to the system. QuickShape (S42): while it owns a pen stroke, `CanvasInput` sends `StrokeIntent::Hold` every frame with the input clock and 5 points in canvas pixels, and asks for frames, so a pen resting without events still holds; contacts on a snapped shape's handles (pen or finger) and fingers on the Drawing Guide's centre are routed before everything else (`shape_drag.rs`).

## 5. Persistence

- The store owns the format: one storage format, `openpaint_store::FORMAT` 1 (DECISIONS D95), for the library, OpenPaint files and kept versions; nothing in the code reads an earlier shape. A library or file of another format is refused as `PortError::OtherFormat` before anything is written.
- Editor state (the toolbox: brushes, colours, pen buttons) is stored apart from the artworks; when it cannot be decoded it falls back to defaults and never blocks opening an artwork.
- Autosave runs on a worker when a stroke finishes and when the editor is left; failure shows a clear message with a retry entry.
- The library (D77, D95): `openpaint_store::Library::at(dir)` implements `ProjectStore` on fjall, keyspaces `library` and `projects`; Android keeps it in `getFilesDir()/library`, the harness in `artifacts/`. `records.rs` holds the keys and the head (canvas, id counters, save id, layers with their masks' flags and counts, groups, active layer and target), `strokes.rs` a stroke (id, blend, size, opacity, colour, seed, the recipe stage by stage, samples, clip; `shapes.rs` the shape stage), `fills.rs` an edit record (its kind: 0 fill, 1 cleared pixels, 2 transform with an optional PNG patch, 3 adjustment, `adjusts.rs`, 4 merged layer, `nested.rs`; then the strokes under it), `catalogue.rs` entries and thumbnails, `editor.rs` and `editor_library.rs` the toolbox, `codec.rs` the byte reader and writer, `delta.rs` which records a save writes and removes (slots: a layer's paint, `mask_slot(id)` its mask, a merged layer's id its content, followed into nested records at most `MAX_NESTING` deep), `read.rs` and `write.rs` the calls. `library/format` holds 1; an empty database is marked at its first opening (`library::prepare`). Every save writes a new random save id into the head (`ProjectStore::save` returns it), `write::name` one into a head opened without one; `display_cache.rs` (`DisplayCache`, `CacheKey`, `Cached`) keeps each artwork's shown canvas as one LZ4 block with a CRC-32 outside the library, keyed by it, derived and never read by files, versions or exports.
- Files and versions (D62, D63): `artwork_file.rs` writes a project as an OpenPaint file (magic, format, title, its records keyed without the project id, its head's save id 0, CRC-32) and opens one (the magic, the format, the sum, then `read::artwork` over a `Source`, the trait both the keyspace and a file's held records implement); `write::add` stores an opened file as a new project (its thumbnail too). `versions.rs`: a version is a file's bytes under `[project]['v'][n]` with a dated entry `['v'][project][n]` in `library`; listing reads the entries only; delete removes both, duplicate skips them.
- Robustness (D77): every write goes through one `batch.rs` `Batch` per call (fjall's atomic, journaled batch: a save lands whole or not at all, also when the process is killed or the disk fills mid-write; the store's unit tests fail its n-th write through a test-only hook and cut the journal at every byte of a save). A record that does not decode or breaks an artwork rule fails only that artwork's opening. The runtime commits the stroke being drawn (`Session::end_stroke`) in `leave` and `detach` before handing the version to the store.
- Tests: one frozen sample, `store/tests/samples/format-1.bin` (`tests/format.rs`, `tests/sample/`), holding every record kind; storing the sample gives its bytes exactly, opening it gives the sample artwork and toolbox, storing what it opened gives the bytes again; libraries and files of another format are refused untouched.
- Colour (S27, D53): inside the app every pixel is sRGB-encoded. Colour management lives only at the file boundary, `store/src/colour.rs` on moxcms: `decode_image` (insert and reference) converts a file's embedded RGB ICC profile (PNG `iCCP`, JPEG APP2) into sRGB on straight RGBA8, keeps untagged and sRGB files bit for bit, takes unusable, grey and CMYK profiles as sRGB; `encode_image` embeds the fixed sRGB profile `store/assets/srgb.icc` in every PNG and JPEG export. Since S29 (D55) exports are written by `export_file.rs`: `ImageEncoder { new(format, size), rows(rgba), finish() -> bytes }` takes bands of whole rows, a PNG through png's stream writer (png 0.18.1 is a store dependency now), a JPEG collected as RGB and encoded at the end; `encode_image` is one band of it; the runtime's transfer worker streams `Core::export_bands` into it and writes the file once. The window surface is configured in `SurfaceColorSpace::Srgb` (`render/src/surface.rs`, `Surface::report` logs the offered formats and colour spaces at attach), in Rgb10a2Unorm where offered (S37, D64: the screen's canvas and tiers hold ten-bit codes; every read, export and file stays 8-bit sRGB).

## 6. Brushes and rendering

- A brush is a declarative recipe (TOML): softness, size and opacity curves over pressure, speed and tilt, grain, deposit, taper, shape. Rendering evaluates per pixel along the stroke (since S34 along the curve through its knots, D71), its stamps too (D72); there is no stamp engine, no node graph, no shader plugin.
- Landed in S45 (D72): the shape stage (`core::Shape`: `Stamp` disc, square, ellipse or a `ShapeTexture`, aspect, spacing, scatter, `Rotation` and angle, rotation and size jitter; `jitter(seed, n)`; `MAX_STAMPS`), `StrokeStyle::seed`. A stamped span's op carries its length at its start, its first and last stamp and where its stroke's paint op lies (`render/src/stroke_stamp.rs`, `protocol_stamp.rs`); the paint op carries the shape; `shaders/stamp.wgsl` lays each stamp the pixel's projection onto the span's chords can reach, `stamp_texture.wgsl` reads the shape textures (`shapes.rs`: distance and coverage mips, after the paper in `Core::textures`). `cargo shape-assets` (`xtask/src/shapes.rs`) makes the textures; the runtime's `Seeds` gives each stroke its seed (`Runtime::fix_seed` in the harness). Built-ins after Soft Brush: Textured Round, Flat, Opaque Paint, Speckle; harness `brush-sheet` paints every built-in at 1x and 4x.
- A stroke stores a recipe snapshot; reopening an artwork never silently applies a renamed brush's new behaviour.
- Landed in S46 (D73): the library is the user's. `app::BrushLibrary` holds the brushes in picker order and the built-ins as their files have them (Reset's values); `BrushKey` is an owned string (`copy-<n>` for copies, with their source); `brush_edit.rs` applies a `BrushChange` to a recipe's plain data inside the ranges `brush_fit.rs` computes, checked by `BrushRecipe::from_parts`; the library is stored in the toolbox record (built-ins as their files by key alone, every other brush whole) and a stored brush the engine refuses falls back to its built-in.
- Landed in S47 (D74): `app::BrushSets` (`brush_sets.rs`) keeps where each brush lies, every brush in exactly one of the four `BrushSet`s in the hand's order, a brush in no stored set placed where a first start puts it, and Recent, the brushes of the last six committed strokes of any tool (`Session::stroke_committed`, which the runtime hands to `Toolbox::drew`), newest first; `BrushProjection::{sets, set, rows}` list them, `BrushIntent::{Reorder, MoveToSet}` change them, and the toolbox record stores them beside the library.
- Landed in S11 (D27): stages softness, size and opacity dynamics (pressure x speed curves) and grain. Built-ins Pencil, Ink Pen (= the plain round brush, the default) and Soft Brush.
- Landed in S44 (D71): tilt is a third factor of the size and opacity dynamics (`Dynamics::with_tilt`, a curve over degrees from upright; a size may grow up to `MAX_GAIN` 4 with `Curve::gain`), evaluated per knot in `render::stroke::dab`. The taper stage (`core::Taper`: start and end in diameters, the tip's share) multiplies each knot's radius by the smaller of two smoothsteps along the path's chords (`render/src/stroke_path.rs`: `Path::of` drawn without the end taper, `Path::lifted` for finished strokes in `segments`), and `ActiveTrack` evaluates again the spans within the end taper when a stroke lifts (`lift_region`). Built-ins by job: Pencil (with tilt), Ink Pen, Inker, Monoline, Hard Round, Soft Brush; a brush file's `streamline` is its StreamLine at first. Azimuth turns stamps (S45).
- Landed in S16 (D38): the deposit stage. Ink Pen covers (crossings never darken); Pencil accumulates graphite under a flat tip on the canvas-fixed sketch paper (draweave's tuned values); Soft Brush accumulates under a bell. Density is laid per radius travelled, capped by the stroke's opacity.
- Landed in S21 (D46): the smudge, a third tool with the same recipes: contacts along the path carry the layer's colour; evaluated once per stroke into a residual, not per pixel (the one exception to "no dab engine", because a smudge reads its neighbours). Landed in S33 (D59): Gaussian Blur and Sharpen read their neighbours too: each record is filtered once at canvas resolution into an arena block the renderer then reads per pixel.
- Landed in S57 to S65 (D84, D86 to D92) and S66 (D93): the raster core draws every scene for every reader (the module map in section 3); a stroke's pieces and stamps are instanced quads computing each pixel's coverage into a float atlas combined by the blend unit, then laid onto a float layer by its paint blend; smudges, adjustments and filters rewrite their layer from a copy; transform records draw in their frame, moved and merged content on level targets, groups over a copy of what lay under them; each layer ends by fixed-function blending or from a copied backdrop. Since S66 there is no interpreter, binning or cost table; the tests hold the core to its own invariants and to formulas (`render/tests/stroke/exact.rs`).
- Export always uses native precision; the screen shows a fast result first and swaps in the refined one when background work completes, without changing extent or strength.

## 7. Errors

`CoreError` (artwork semantics), `AppError` (modes and flows), `PortError` (external capabilities), `RenderError`, `RuntimeError`. The platform layer translates them into user-facing messages; `String` appears only in JNI, system APIs and xtask.

Storage failures are contained per call and per artwork (D77): a failed write leaves the library as before the call (the save's notice with Retry; a failed kept version is only logged), and a record that cannot be read fails only that artwork's opening ("Couldn't open this artwork"), never the library. A library or file of another format is `PortError::OtherFormat` (D95): the gallery says it is from another version and nothing is written.

A lost GPU device is not an error the user sees (S49, D76): wgpu's lost callback, out of memory or a driver failure mark the `Core` lost (`Core::lost`; the runtime's `Core::catch_errors` keeps every later call on it from panicking), and a frame that finds it so, or fails with `RenderError::Device` or `Timeout`, makes the renderer again on a new device (`runtime/src/recover.rs`) before it goes on. Workers take the current core per job from `SharedCore`, so a job running at the loss fails as any GPU failure does and the next one runs on the new device; app state (artwork, history, toolbox, session, the stroke being drawn) is never touched.

## 10. UI conventions

The UI is designed from the user inward (AGENTS.md, "Design from the user inward"). These are the fixed defaults.

- The default interaction model is Procreate's. Before building a feature, read its Procreate Handbook page (entry point, gesture, feedback) and follow it. Deviate only for Android tablet hardware or on the author's instruction. Never copy icons, colours or assets.
- Layout skeleton (S17, D40): the canvas shows on the whole screen; the controls float over it as ink-outlined `island`s and nothing spans the width: Gallery and Actions at the top left, Brush, Eraser, Layers and the colour at the top right, the side bar at the left edge (can be mirrored for left-handed use). The canvas fits under the 48-point top band (`CanvasArea { screen, fit }`), so at fit the top islands lie on the desk. Panels are popovers over the canvas and close with one tap outside. A modal appears only before a destructive action. What comes and goes is a `pill` in the top band: notices left of the right island, the fill bar and the view's zoom in its middle.
- Popovers (S9, `components::popover`): anchored under the right island (Actions under the left one), growing out of their island button (S19), usable from the frame they open. A contact starting on a popover or an island never reaches the canvas (`CanvasInput::route` takes the covers); a contact landing on the canvas outside closes it, and a pen stroke there draws. Components: `icon_button`, `icon_toggle` (an ink ring while its panel is open), `text_button` (a command: a bare word in ink, the press wash under the hand; S25), `choices` (a group of mutually exclusive items in one container owning their one mark: `text_choice` / `text_choice_wide`, a word whose chosen one carries the ink pill, the icon ring's line round the word; `icon_choice`, the tools' ring; G3 follow-ups), `divider` (a faint upright line between a bar's choice and its commands, or a pill's message and its action), `hint` (a quieter line saying what something does), `command_row` (a leading icon and words in ink: Add Mask), `list_row` (chosen row outlined in ink, an icon button at its end), `slider` (value and `settled`), `notice`, `popover`, `island`, `pill`; since S10 `dialog` (over a veiled screen, centred or under the islands; a tap outside cancels), `text_field`, `artwork_card` (the thumbnail as a sheet on the desk).

- The theme is defined once in `ui/src/design/` (D32, D40): `palette.rs` (paper, desk, ink, the deeper active ink, outline weight), `paint.rs` (panel frame; `Outline`, the shape of a control's mark: the icon ring, the same ring as a pill round a word, the row outline; the press wash fills exactly that outline, never the wider 48-point hit area; the divider, ink lines with round joins, sheet shadow), `icons.rs` (self-drawn ink-line icons in one 1.5-point weight behind a semantic `Icon` enum), `fonts.rs` (the host's system sans and Chinese face in front of the built-in one), an 8-point spacing scale, one type scale (18-point body). Every button, slider and panel is a component in `ui/src/components/`; screens compose components and never style widgets inline. One ring rule (S25): the ink ring means chosen, for words as for icons; at rest nothing the hand taps is framed (a bare word in ink is a command, quieter grey is a hint), so never a frame inside a frame. Intuitive (a first-day user needs no instructions) and restrained (UI appears when needed; cues over controls); hidden shortcuts only duplicate a visible control.
- Every feature ships with a discoverable entry, visible feedback for success, failure and cancel, undo for anything that changes the artwork, and state that survives reopen. Missing any of these means the slice is not done.
- Checklist that harness screenshots and scenarios must show: the most frequent actions (brush, size, opacity, colour, undo, layer) within two taps; hit targets at least 48 points at tablet density (the icon is not the hit area); nothing covers the canvas while a stroke is possible; feedback within one frame; the same component for the same job everywhere.
- Motion (D44). Motion only explains: where something comes from or goes, what changed, that input arrived. Never on the drawing path (strokes, canvas navigation, slider drags follow the contact 1:1); interruptible, never blocks input, retargets instead of queueing; critically damped unless a gesture released momentum; open about 0.4 s or less, close faster; elapsed time, never per frame. Four patterns, built into the shared components; screens only declare state and never animate by hand; a new pattern needs a decision:
  - emerge / retract: a surface grows from its source and returns to it (panels from their island button, dialogs, notices, the loupe, the reference window, a gallery card into the canvas);
  - fade through: unrelated content in one place (switching panels: the old one retracts into its own button, the tapped one grows from its button and finishes last);
  - settle: things that move, appear or leave make room (layer rows, around a dragged row and the row let go, which follows the hand 1:1 while carried, quick pinch to fit, the chosen mark of a `choices` group sliding and resizing to the item chosen, retargeting mid-slide, never across groups or islands; in place when the group first shows);
  - acknowledge: a state changes in place (a toggle's ink ring, a mark appearing or going with no choice before or after it, switches, swatches, the selection hatch).
  No motion for canvas content changes (undo included), the ColorDrop dot, slider drags or the hover outline.
  Landed in S19: `design/motion.rs` (`Spring`, `Feel`, presets `OPEN`, `CLOSE`, `RETRACT`, `SETTLE`, `ACKNOWLEDGE`, the switch delay, pour and reveal); springs live in egui's memory and step by egui's input time (`components::animate`, `settle`). `components::chrome` keeps every surface's `Growth` (`surface.rs`): a surface only declares each pass whether it is open and its `Source` (`Button` on an island, `Rect`, `Within` its own end); content is laid out at its finished place (taps hit the final state; a closing panel's area is not interactable), and `chrome_frame.rs` clips its shapes to the moving shape and fades it in. Islands (`island`) and the panels growing out of them (`popover`, `Opener`) are one SDF silhouette drawn by `render::chrome_shape` (`adapter/chrome.rs`, `shaders/chrome.wgsl`; one paint callback per island's reach, all sharing one uniform) in a Foreground layer under the islands' and panels' content; pills, dialogs, the loupe and the reference window are separate paper (`paper.rs`) that retracts with no content once no longer shown. A screen switch drops what the old screen showed. The view settles through `ViewSettle` (display only; `ViewMapping::{placed, toward}`; any canvas contact stops it); the gallery card and the canvas through `carry.rs`. The runtime's `FrameClock` is real time, or `Runtime::fix_clock` in the harness; `Runtime::moving`.
- Lessons carried over from draweave (D33; each was a failed author check or a fix there):
  - Controls have three states: available; unavailable (greyed, nothing to act on); temporarily blocked (normal look and hit area, the action is refused at the intent). An active stroke or a captured panel only ever blocks temporarily; nothing greys out or flickers per stroke.
  - Any control that takes a contact resets the gesture trackers, so a button tap never lingers as a canvas gesture. Gestures read raw touch geometry including the release positions (Android batches the last move with the up).
  - A tap outside a panel closes it and consumes only that contact; the next contact draws. The tap that opens a panel never dismisses it. Panels float and never shrink the canvas; they size to their content.
  - Sliders say what they set (a label or end icons plus the live value), show a preview while dragging (size: a circle at the real size; opacity: a swatch at that alpha), restore the original value on cancel or focus loss, and belong to one contact at a time.
  - The pen's hover shows the brush outline at full size, a 1-point line contrasting with the canvas under it, hidden over controls and during multi-touch. The eyedropper commits the last valid preview, not where the contact drifted on release.
  - Animations advance by elapsed time, never per frame. Notices are brief; quiet success, persistent failure. Every icon-only button has an accessible name and a hover label; new concepts and destructive actions use icon and text.

# Architecture

OpenPaint is an Android-first, stylus-first 2D painting app whose goal is to take an illustration from sketch to delivery on one tablet. Android is the only product host. On the development machine a headless harness renders offscreen, replays recorded input and runs scenarios; there is no desktop window and no desktop product.

This page is the design contract: how modules are cut, which way dependencies point, what the core types look like, how threads and errors are handled. When code and this page disagree, change the code or change this page and record a decision; never keep both.

## 1. Principles

1. One concept has one definition and one owner, and the owner is a module, not just a crate. Mutable/immutable, intent/command and persistent/session forms are never kept twice.
2. The artwork is an immutable value. An edit produces a new version, history stores versions, undo switches versions (D08).
3. Product crates have no `cfg(feature)`. Diagnostics, experiments and automation probes live in separate crates and are assembled only by composition roots (D10).
4. The renderer depends on core only. GPU state belongs to the renderer's own `Core`, never to the UI framework. One render core, the raster core, draws every scene for every reader (D92, D93); the GPU protocol is defined once in Rust, injected into WGSL and proven by layout tests.
5. Strokes and operation records are the truth; every pixel is a derived, discardable cache.
6. Pay per change: saving, history budgets and projections touch only the data a change involves; the UI thread never does work proportional to artwork size.
7. Errors are types. `String` errors are allowed only in JNI, at system boundaries and in xtask.
8. One user action has one product path: no double writes, no simple/advanced variants, no silent fallbacks, no modules or abstractions reserved for features not yet accepted.
9. Files at most 400 lines, functions at most 60 lines, tool-enforced; `lib.rs` holds only `mod` and `pub use`.

## 2. Crate map

| `openpaint-store` | the local library (storage format 1), OpenPaint files, kept versions, image files, the display cache; implements the app ports | core, app | GPU, UI |

| `openpaint-devtools` | scenario files, the scenario runner, checkpoint diffs, the switchable store wrapper `Watched` | product crates | product rules; never a dependency of a product crate |
| `openpaint-harness` | development harness: `scenario` (`--all` on parallel workers, each scenario a process of its own: `scenarios.rs`), test art, replay, statistics, PNG and hash output; `key-shifts` (S107: the key shift checks on the built packs' crops, contact sheets); never shipped | all, devtools, sheet | windowing, mouse input, product rules |
| `openpaint-sheet` | the harness's and the pack builder's contact sheets (S111) | nothing | product code |

| `tools/packs` | a workspace of its own outside the gate, built in its `target/` (S111): `cargo practice-pack build|search`, a pack from a list (`lists/`; web clients `sources.rs`, `libraries.rs`), downloads cached in `artifacts/packs/cache/`; U²-Net via tract-onnx (`segment.rs`, D106), value masses (D108), crops from full pixels (`crops.rs`, D105), contact sheets | practice, app, store, sheet, by path | product code; a second implementation of the app's computations |

Dependencies only point down (`A <- B` means B depends on A):

```text
core <- app <- store
core <- app <- ui <- runtime <- {harness, android}
core <- render <- ui
core <- raster <- runtime
practice <- app; practice <- store, ui, runtime
store, render <- runtime
runtime <- devtools <- harness
sheet <- {harness, tools/packs}; practice, app, store <- tools/packs
```

A new crate is registered in `LAYERS` in `xtask/src/check/rules.rs` first (D02). The app's version is `[workspace.package] version` in the root manifest; `xtask/src/version.rs` hands it to Gradle with the store's `FORMAT` as build metadata and a version code, and the runtime hands the same two to the shell (`Shell::set_version`), which shows them as Actions' last line in the language shown (D79).

## 3. Core types

### core


No public mutable setters. Layers come only from `from_storage` (the single full-validation entry, `ArtworkParts`, `parts*.rs`) or commands; `to_parts` gives plain data for the store. A command that changes nothing returns `Change::None` and the same version. Ids are never reused; limits (`MAX_LAYERS`, `MAX_STROKE_SAMPLES`, `MAX_CANVAS_SIDE`, `MAX_NESTING`, `MAX_STAMPS`) are public constants. The modules:

- Layers and groups: `layer.rs`, `layer_command.rs` (`Create`, `Delete`, `Select`, `Rename`, `Move { layer, by }`, `Duplicate`, `MergeDown`, visibility, opacity, lock, Alpha Lock, clipping, blend), `layer_moves.rs` (`stepped`, `layer_places`: one step's rule into and out of groups), `group.rs`, `group_command.rs`, `blend.rs`, `mask.rs` and `mask_command.rs` (D51), `merge.rs` (`Artwork::mergeable -> Result<(), Unmergeable>`, D66).
- Strokes: `stroke.rs`, `session.rs` (`StrokeSession`: extend, `revise` its end, `reshape` it whole, finish, cancel; the active stroke is not in a layer), `stroke_list.rs`.
- Recipes (D74): `brush.rs` (`BrushRecipe`, `Dynamics { pressure, speed, tilt }`, `Curve`), `deposit.rs` (`Cover` or `Accumulate`, paper; D38), `taper.rs`, `shape.rs` (`Shape`, `Stamp`, `ShapeTexture`, `jitter`).
- Records: `fill.rs` (`FillEdit`, `Artwork::fill_region`), `clear.rs`, `transform.rs` (`Placement`, `Patch`, `place_region`, `transform_region`; D57), `adjust.rs` and `tone.rs` (`Adjustment`, `ToneCurve`), `filter.rs` (`Blur`, `Sharpen`; D59), `nested.rs` (`NestedLayer`), `copy.rs` (`Copied`, `copied`, `paste`, `cut`; D67), `region.rs` and `mask_ops.rs` (`RegionMask`: polygon, union, intersect, inverted, whole; D43).

The UI reads projections, keeps UI-local state and emits intents; availability and value ranges come from the projection (`Availability`, `EditorAction`), so the UI never assembles rules itself. Each intent family is one module holding its intents, handlers, projection and tests:

- The session per artwork (`session*.rs`): history (`history.rs`: versions costed by `bytes_since`, 64 MiB, D20; on a sheet Next keeps only the current one, D105), strokes (`stroke.rs`, `stroke_shape.rs`, `stroke_copies.rs`, `streamline.rs`, `quickshape*.rs`, `symmetry.rs`; D69, D71), layers (`layers.rs`, `layer_rules.rs` with `LayerRefusal`, the one Hidden/Locked check fill, adjust and transform make), selection (`selection.rs`), fill (`fill.rs`: `FillJob`s for the fill worker, newest only), transform (`transform.rs`, `transform_insert.rs`: a draft with its own steps; inserts and pastes are drafts on a new layer), adjust (`adjust.rs`), clipboard (`clipboard.rs`, `session_clipboard.rs`), storage (`storage.rs`, `session_storage.rs`: the autosave flow). ### render

```rust
pub struct Core { gpu, textures /* paper and shapes */, pace: Mutex<Pace>, raster pipelines, frames, .. }
pub struct FrameRequest<'a> { artwork, active, background, .. }
impl CanvasTarget { pub fn draw(..); pub fn draw_frame(..); pub fn whole(..) -> RgbaImage; }
pub enum RenderError { Admission { what, limit }, Cancelled, MissingImage, Device(String),
                       Invalid(&'static str), Timeout { what, seconds } }   // every GPU wait ends within 30 s
```

One render core, the raster core (D92, D93): every scene is drawn by the GPU's rasterizer as instanced quads computing each pixel's coverage into a float atlas, laid onto float layers by their paint blend, layers ending by fixed-function blending or from a copied backdrop. The module map:

- Scene: `scene.rs` (`Scene::build_knowing(&FrameRequest)`: visible layers, records, smudges, adjustments, filters, frames, moves and nested records as `Item`s and `Op`s in drawing order with conservative canvas bounds), `scene_content.rs`, `scene_layer.rs`, `scene_adjust.rs`, `scene_nested.rs`, `scene_cleared.rs`, `scene_fresh.rs`, `scene_append.rs` (appended strokes taken in place), `scene_reuse.rs` (spans copied from the scene before), `scene_ops.rs` (`SceneOps` on the GPU), `edits.rs`, `stroke.rs`, `stroke_path.rs`, `stroke_stamp.rs`, `curve.rs`, `fill_edge.rs` (D56), `shapes.rs`, `paper.rs`, `active.rs` (the tracked stroke), `change.rs` (`changed_regions`), `preview.rs`. `protocol.rs` and `protocol_*.rs` own `Op` (its operands, named slots and the WGSL prelude generated from them, checked by a naga layout test).
- Raster core: `raster_scene.rs` (`Scene::raster`: units per item), `raster_plan*.rs` (`RasterPlan`: a region's `Pass`es; drawing, kept coverage, records, ends), `raster_lay.rs` (`Placing`, `material_reach`), `raster_kinds.rs`, `raster_slots.rs`, `raster_reads.rs`, `raster_frame.rs` (passes encoded), `raster_batch.rs` (a frame's regions one command buffer), `raster.rs` (`RasterTargets`), `raster_gpu.rs` (`raster_source()`: raster.wgsl, raster_stamp.wgsl, raster_composite.wgsl, raster_paint.wgsl and the stroke, stamp, deposit, fill-edge, smudge, adjust and filter shaders; the pipelines), `raster_states.rs` (formats, blends, layouts), `raster_worker.rs` (`RasterJob`, `RasterOrder`, `RasterDone`, `RasterAnswer`, `RasterDrawer`: what the runtime's raster worker draws), `geom.rs` (`PixelRect`, `Bounds`), `output.rs` (`Output`: a target's scale, D55), `affine.rs`.
- The canvas: `canvas.rs` (`CanvasTarget`: the screen's target, `draw`, `draw_frame`, `whole`; `pick` reads it back) and its parts in `canvas/`: `raster.rs`, `raster_fill.rs`, `raster_hand.rs` (waiting 256-px tiles handed to the raster worker into staging slots, changes in place, reads of the whole), `scene_cache.rs` and `retune.rs` (the kept scene, retunes and appends in place), `residuals.rs`, `budget.rs` (bytes, rooms, the arena's shrink), `cache.rs` (the display cache's copies), `drawing*.rs` (the stroke being drawn from snapshots per output tile, D91).
- View tiers (D85, D93): `view_tier.rs` (`ViewCache`), `view_tiles.rs`, `view_atlas.rs`, `view_needed.rs`, `view_kept.rs` (`HeldTier`), `view_fill.rs`, `view_raster.rs`, `view_raster_fill.rs`, `view_shown.rs` (the blit's bindings; the atlas filterable: four texels inside one tile are one hardware bilinear sample, across a tile's edge four reads through the index).
- Readers: `export.rs` and `export_raster.rs` (bands of pieces; `export_region`, a region at 1x for a painted practice copy), `sample.rs` (layer and mask pixels for fill and lift), `thumbnail.rs`, `readback.rs` (`eight_bits` from ten-bit codes, D64), `underlay.rs`, `difference.rs` (`image_difference` for tests and devtools).
- Smudges and filters: `smudge.rs` and `smudge/` (residuals, `Arena`, `Held`, `Bases`, `Material`, kernels; D46), `filter.rs` and `filter/kernels.rs` (results in the arena, D59).

Background consumers (export, fill, pick, pictures) hold only an `Arc<Core>` and never touch a UI lock. Incremental and cold drawing are bit-identical, proven by GPU tests (`render/tests/stroke/`).

## 4. Input

Hosts deliver platform events as `runtime::MotionBatch` (phase, buttons, pointers with tool kind and batched samples: position, pressure, tilt, orientation, time); the Android host decodes `MotionEvent` arrays into it in `apps/android/src/motion.rs`. The Android host and the harness feed one normaliser (`runtime/src/normalise.rs`): `MotionBatch` -> `app::InputBatch` (per contact: id, device, phase, samples; ranges clamped, times monotonic per contact). egui receives its pointer events from these batches; no windowing library sits in between.
Palm rejection (`app::PalmRejection`) applies to every batch before egui or the canvas sees it: while a pen contact is down, touches are palms until they lift; a pen landing cancels the touches already down. The UI's canvas input (`ui/src/canvas_input.rs`) owns each pen contact that touches down on open canvas and hands it to the session as `Intent::Stroke` mapped through the view into canvas pixels (any contact, picking, while the eyedropper is on); it follows the hovering pen for the brush outline.
Finger contacts go to `app::Gestures`, which decides in points what they mean (navigation, quick pinch, taps, the three-finger swipe). Contacts on the reference window, a ColorDrop drag, a snapped shape's handles, the guide's centre, the transform frame and the brush strip are routed from the raw batches before the canvas. Platform cancels arrive as `Cancel`; egui gets a cancel as a release far off screen. The stroke intent drops Android's zero-pressure lift sample. The pen's side buttons are read from every pen event's button state into `InputBatch::pen` and handed to `app::ButtonTracker` before and after each batch's contacts (D70). StreamLine lives in the stroke intent; the stored samples are the smoothed path. Keyboard text reaches egui as IME and key events through `Runtime::text`; the host shows the soft keyboard while `keyboard_wanted` (the host is the text editor, no `EditText`); the back button goes to `Runtime::back`.

## 5. Persistence

- The store owns the format: one storage format, `openpaint_store::FORMAT` 1 (D95), for the library, OpenPaint files and kept versions. A library or file of another format is refused as `PortError::OtherFormat` before anything is written.
- The library (D77): `Library::at(dir)` implements `ProjectStore` on fjall, keyspaces `library` and `projects`; Android keeps it in `getFilesDir()/library`, the harness in `artifacts/`. `records.rs` the keys and the head, `strokes.rs` and `shapes.rs` a stroke, `edits.rs` an edit record (`write_optional_mask`; `adjusts.rs`, `nested.rs`), `catalogue.rs` entries and thumbnails, `editor.rs` and `editor_library.rs` the toolbox (the language a byte at its end once chosen, D100), `codec.rs` the byte reader and writer, `delta.rs` which records a save writes and removes, `read.rs` and `write.rs` the calls, `batch.rs` the one atomic batch per call, `library.rs` (`prepare` marks an empty database). Every save writes a new random save id into the head.
- Files and versions (D62, D63): `artwork_file.rs` writes and opens OpenPaint files over the same `read::artwork` as the library (a `Source` both implement); `versions.rs` keeps a version as a file's bytes with a dated entry.
- Practice (D98, D99, D102, additive to format 1): `practice.rs`, a session's record under `['p'][session u64]` in `library`, its results' tail (compares, the first correction's stroke id) after them, absent in 1.1.0's records, then the warm-up's count, absent before 1.3.0, the pictures, then the spans its sheet was practised in (1.7.0, D109; a record without them is given its time from its compares by the store's upgrade when the library opens, `library::prepare`, which also gives a value scale stored as 1.14.0 did, (6, tone), its cells in its kind and its seed one draw on, S97), then its layout byte (1.17.0, S99: frames of their pictures; a record without it has its sheet laid anew once by the store's upgrade, `practice_frames.rs`, given the packs, `Library::with_packs`: each stroke and fill begun in a copy's square moved from the picture's place there onto the frame of its shape, sheet and record in one batch); a long colour copy is such a record of stage 0, its name its sheet's title (`titles`, D105), a drill one of stage 255 (D110); `start_practice` writes a sheet's project and its record in one batch, `remove_practice` removes both in one (the test-session chore); `list` leaves the sheets out; `sheet` reads one for the practice book without writing; an unreadable record is left out of `practice`.
- Packs (D101, D103): `store/src/pack.rs` (the file: magic, `PACK_FORMAT` 4, a checked head with each item's credit or none, outline or none, value masses (runs) or none and colour areas (colours, runs) or none, pictures), `pack_upgrade.rs` (a format-2 or 3 pack given its items' "none" for what its layout lacked, on import and for a pack kept, the personal one too; nothing else reads an older pack), `pack_picture.rs` (a picture as a pack holds it, the same for the builder and the user's own: decoded, at most 2048, PNG if transparent else JPEG; `shown_picture` reduced to 1024 for the screen, `thumbnail_picture` for the options) and `packs.rs` (`Packs::at(dir)`: `<dir>/<id>.pack` beside the library, import checked whole and renamed into place (never the personal pack), `add_picture` at a tier writing the personal pack whole again with the new one last (its id from the file's CRC-32), `remove_picture` and `set_tier` likewise, `list` from heads, `picture(&ItemRef)` by offset and check sum); a non-pack file is `PortError::Corrupt { what: "practice pack" }`; the library's records never touched. - Images (`colour.rs`, `image_file.rs`, `export_file.rs`; D53, D55): decoding with colour conversion into sRGB; `ImageEncoder` takes bands of rows (PNG streamed, JPEG at the end) and embeds the sRGB profile.

- Tests: one frozen sample, `store/tests/samples/format-1.bin` (`tests/format.rs`, `tests/sample/`), holding every record kind; the store's unit tests fail its n-th write through a test-only hook and cut the journal at every byte of a save.

## 6. Brushes and rendering

- A brush is a declarative recipe (TOML in `app/brushes/`; the practice pens' own in `app/pens/` (S100), their hard tip Hard Paint's file (S104)): softness, size and opacity curves over pressure, speed and tilt, grain, deposit, taper, shape (D74). Rendering draws per pixel along the curve through the stroke's knots (D71), its stamps too; there is no node graph or shader plugin. A stroke stores its recipe's snapshot and its seed; reopening never applies a brush's later edits.
- The deposit (D38): covering strokes keep the largest coverage; accumulating ones lay density (the Pencil on canvas-fixed sketch paper, the Soft Brush under a bell). Shapes: stamps belong to the span whose length range holds them, textures from `cargo shape-assets` (`xtask/src/shapes.rs`).
- The smudge reads its neighbours, so it is drawn once per stroke into a residual (D46); Gaussian Blur and Sharpen likewise into arena blocks (D59). Everything else is drawn per pixel by the raster core.
- Exports draw at their scale (D55), the 1x export is the canvas pixel for pixel, a tier tile is its export (D93).

## 7. Errors

`CoreError` (artwork semantics), `AppError` (modes and flows, refusals such as `LayerRefusal`), `PortError` (external capabilities), `RenderError`, `RuntimeError`. The platform layer translates them into user-facing messages; `String` appears only in JNI, system APIs and xtask.

Storage failures are contained per call and per artwork (D77): a failed write leaves the library as before the call (the save's notice with Retry; a failed kept version is only logged), and a record that cannot be read fails only that artwork's opening ("Couldn't open this artwork"), never the library. A library or file of another format is `PortError::OtherFormat` (D95).

A lost GPU device is not an error the user sees (D96): wgpu's lost callback, out of memory or a driver failure mark the `Core` lost, and a frame that finds it so, or fails with `RenderError::Device` or `Timeout`, makes the renderer again on a new device (`runtime/src/recover.rs`) before it goes on; a job running on a worker at the loss fails as any GPU failure does; app state is never touched.

A spot is a control's name (`name #n` when shared), `{ on, fraction, offset }`, or window pixels on the canvas only; pixels on a control fail the run with the name to write. `openpaint_devtools::run` turns gestures into `MotionBatch`es and drives `Runtime` offscreen on a library directory and a packs directory beside it; the runner holds the clock (batch times, then 16 ms a frame), lets motion settle before steps that look (a `screenshot` with `after_ms` catches a motion mid-way), fixes every stroke's seed and opens one device with an 8-bit screen. `cargo scenario <name>` writes PNGs and failure diffs under `artifacts/scenarios/<name>/`; the gate runs `smoke`.

`device-clean`, `device-screens` (`screens.rs`: the tablet's newest screenshots pulled and listed, nothing changed), `device-push` (`--download`: into `/sdcard/Download/` for the author), `device-info` (read-only `getprop` and `dumpsys`, `--watch`), `device-idle` (`idle.rs`: the screen, the app in front and the minutes since the last touch, pen or key from `dumpsys power`; exit 0 when untouched 10 minutes or more or the screen is off, every routine starting with it; the agents' own injected gestures count as touches), `device-smoke` (`smoke.rs`, `smoke_checks.rs`: a fixed list of steps on a test artwork it makes and deletes) and `device-reset` (`reset.rs`: `pm clear`, refused without a backup written the same UTC day).

## 9. Enforced rules

`cargo repo-check` (`xtask/src/check/`, over tracked and new unignored files): .rs files at most 400 lines; dependency direction per section 2; purity tokens per crate (core never mentions serde; devtools never touches `std::fs`); egui in render only under `adapter/`; no cargo features in product crates; crate roots carry `#![forbid(unsafe_code)]` (android and the harness's allocator excepted); markdown only the four documents (within their lines and characters, 1,500 a line: `lengths.rs`), README, AGENTS.md and the archive; no script files; no CRLF; `tools/packs` with the root's lints, its rustfmt and clippy run (`tools.rs`); under `crates/ui/src/` outside `text/` and tests no literal reading as words (a capital, then a small letter) and none handed to `Words::made` or `named` (`words.rs`, D100); outside practice and the tests no arm or `matches!` over its `Kind` (`kinds.rs`, S109). clippy: functions at most 60 lines, no `todo!` / `unimplemented!` / `dbg!`, warnings are errors; a justified exception is `#[expect(lint, reason = "...")]`, never `#[allow]`.

## 10. UI conventions

The UI is designed from the user inward (AGENTS.md, "Design from the user inward"). These are the fixed defaults.

- The default interaction model is Procreate's. Before building a feature, read its Procreate Handbook page (entry point, gesture, feedback) and follow it. Deviate only for Android tablet hardware or on the author's instruction. Never copy icons, colours or assets.
- Layout skeleton (D40): the canvas shows on the whole screen; the controls float over it as ink-outlined `island`s and nothing spans the width: Gallery, Actions, Adjustments, Selection and Transform at the top left; Brush, Smudge, Eraser, Layers and the colour at the top right; the side bar (size and opacity sliders, the eyedropper, undo and redo) at the left edge. The canvas fits under the 48-point top band (`CanvasArea { screen, fit }`). Panels are popovers over the canvas, one at a time, and close with one tap outside. A modal appears only before a destructive action. What comes and goes is a `pill` in the top band: notices left of the right island; the fill, selection, transform, shape and copy bars and the view's zoom in its middle.
- Components (`ui/src/components/`): `island`, `popover` (grown out of its island button, usable from the frame it opens), `icon_button`, `icon_toggle`, `text_button` (a command: a bare word in ink with the press wash), `choices` (a group of mutually exclusive items owning their one mark: `text_choice`, `text_choice_wide`, `icon_choice`; `word_columns` lays words out in two columns with a `Lead`), `divider`, `hint` (a quieter line), `command_row`, `menu_row`, `label_row`, `panel_heading` / `panel_heading_with`, `list_row` (the chosen row outlined, an icon at its end; `picture_row`: a picture small beside its title and a line; `row_drag.rs` carries a held row), `slider`, `side_slider`, `setting_slider`, `switch_row`, `swatch`, `color_wheel` (with `color_compare`, two colours as a picture), `colour_table` (how a colour differs: ΔE and its lightness, chroma and hue as strips, bars and numbers, D108), `radar`, `curve_editor`, `preview_strip`, `brush_row`, `notice`, `status`, `pill`, `dialog` (`dialog_of_width` for a page of two columns, `naming_dialog` with `Naming`, `delete_dialog`),
  `kind_tile` (an exercise kind's tile: a fixed line drawing of it and its name, ink once compared, pencil before, ringed while a drill is unfinished, D110), `text_field`, `artwork_card`, `today_card`, `road` (a stage's sessions as dots on a hand-drawn line), `seal` (a vermilion stamp), `card` (`card_text`, `card_columns`, `card_step`: a numbered step, in ink while it is drawn), `wheel_picture` (a demonstration's small wheel), `floating`, `loupe`, `fill_bar`, `view_status`, `canvas_frame`, `picture`. - Every feature ships with a discoverable entry, visible feedback for success, failure and cancel, undo for anything that changes the artwork, and state that survives reopen. Missing any of these means the slice is not done.
- Checklist that harness screenshots and scenarios must show: the most frequent actions (brush, size, opacity, colour, undo, layer) within two taps; hit targets at least 48 points at tablet density; nothing covers the canvas while a stroke is possible; feedback within one frame; the same component for the same job everywhere.
- Motion (D44): motion only explains (where something comes from or goes, what changed, that input arrived); never on the drawing path (strokes, navigation, slider drags follow the contact 1:1); interruptible, retargets instead of queueing; critically damped; about 0.4 s to open, faster to close; elapsed time on the runtime's frame clock. Four patterns, built into the shared components (`components::chrome`, `surface.rs`, `chrome_frame.rs`, `carry.rs`, `view_settle.rs`): emerge / retract (panels from their island button sharing one SDF ink outline with the island, dialogs, notices, the loupe, the reference window, a card into the canvas); fade through (switching panels); settle (layer rows, a dragged row's neighbours, quick pinch to fit, a `choices` group's mark sliding to the item chosen, never across groups); acknowledge (a toggle's ring, switches, swatches). No motion for canvas content changes, the ColorDrop dot, slider drags or the hover outline. Taps always reach the final layout at once.
- Lessons carried over from draweave: controls have three states (available; unavailable, greyed; temporarily blocked, normal look, refused at the intent: an active stroke only ever blocks temporarily); any control that takes a contact resets the gesture trackers; gestures read raw touch geometry including release positions; a tap outside a panel closes it and consumes only that contact; the tap that opens a panel never dismisses it; panels never shrink the canvas; sliders say what they set, preview while dragging and belong to one contact; the pen's hover shows the brush outline at full size, hidden over controls and during multi-touch; the eyedropper commits the last valid preview; notices are brief, success quiet, failure persistent; every icon-only button has an accessible name and a hover label.
- Who decides: details are the agent's. The author judges on the tablet at stage exits. Ask the author in advance only for a deviation from Procreate's mental model, for anything the hand touches continuously (side bar position, gesture mapping, pen buttons) or for anything that changes the persistent format.

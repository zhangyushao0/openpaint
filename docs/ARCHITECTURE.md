# Architecture

OpenPaint is an Android-first, stylus-first 2D painting app whose goal is to take an illustration from sketch to delivery on one tablet. Android is the only product host. On the development machine a headless harness renders offscreen, replays recorded input and runs scenarios; there is no desktop window and no desktop product.

This page is the design contract: how modules are cut, which way dependencies point, what the core types look like, how threads and errors are handled. When code and this page disagree, change the code or change this page and record a decision; never keep both. Type sketches land slice by slice; once landed, code is the truth and this page follows.

## 1. Principles

1. One concept has one definition and one owner, and the owner is a module, not just a crate. Mutable/immutable, intent/command and persistent/session forms are never kept twice.
2. The artwork is an immutable value. An edit produces a new version, history stores versions, undo switches versions.
3. Product crates have no `cfg(feature)`. Diagnostics, experiments and automation probes live in separate crates and are assembled only by composition roots.
4. The renderer depends on core only. GPU state belongs to the renderer's own `Core`, never to the UI framework; "evaluate a batch of regions into a target" has exactly one entry point; the GPU protocol is defined once in Rust, injected into WGSL and proven by layout tests.
5. Pay per change: saving, history budgets, asset reclamation and projections touch only the data this change involves; the UI thread never does work proportional to artwork size.
6. Errors are types. `String` errors are allowed only in JNI, at system boundaries and in xtask output.
7. One user action has one product path: no double writes, no simple/advanced variants, no silent fallbacks, no modules or abstractions reserved for features not yet accepted.
8. Files at most 400 lines, functions at most 60 lines, tool-enforced; `lib.rs` holds only `mod` and `pub use`.

## 2. Crate map

| crate | Responsibility | May depend on | Must not contain |
| --- | --- | --- | --- |
| `openpaint-core` | artwork semantics: layers, strokes, commands, validation, brush recipe data | nothing | GPU, UI, file system, threads, clocks |
| `openpaint-raster` | pure pixel geometry on the CPU: the fill's connected region, a transform's lifted pixels | core | GPU, UI, file system, threads |
| `openpaint-app` | application flow: intents, session, history, workspace, editor state, capability ports (traits) | core | GPU, UI, file system |
| `openpaint-store` | local artwork library: persistent format, schema migrations, assets; implements the app ports | core, app | GPU, UI |
| `openpaint-render` | derived rendering: wgpu pipelines, stroke programs, region evaluation; export, pick and preview consumers | core | file system; `egui` only under `src/adapter/` |
| `openpaint-ui` | shared interface: egui panels, input ownership, canvas arbitration; reads app projections, emits intents | core, app, render | direct wgpu, file system |
| `openpaint-runtime` | frame loop, input normalisation, bounded workers, lifecycle draining, startup | core, app, store, render, ui | JNI |
| `openpaint-devtools` | diagnostics and automation: scenario files, the scenario runner, checkpoint diffs; later observers and statistics | product crates (uses runtime, render) | file system, product rules; never a dependency of a product crate |
| `openpaint-harness` | development harness: offscreen rendering, recorded-input replay, `scenario` command, PNG and hash output; never shipped | all, devtools | windowing, mouse input, product rules |
| `openpaint-android` | the only product composition root: activity lifecycle, Surface, system pickers, JNI | all | product rules |
| `xtask` | repository tooling: `cargo gate`, `cargo repo-check`, the Android build, device chores over adb (`device/`) | nothing | product code |

Dependencies only point down (`A <- B` means B depends on A):

```text
core <- app <- store
core <- app <- ui <- runtime <- {harness, android}
core <- render <- ui
core <- raster <- runtime
store, render <- runtime
runtime <- devtools <- harness
```

A new crate is registered in `LAYERS` in `xtask/src/check/rules.rs` first (raster since S15).

## 3. Core types (target shape)

### core

```rust
pub struct Artwork(Arc<ArtworkState>);           // snapshot as value: clone is O(1), history stores versions
struct ArtworkState { canvas: CanvasSize, background: Background, layers: Vec<Layer>,
                      groups: Vec<LayerGroup>, active: LayerId, ids: IdCounters }
pub struct Layer { id: LayerId, name: Name<80>, props: LayerProps, strokes: StrokeList,
                   image: Option<LayerImage>, edits: Arc<[RegionEdit]> }
pub struct LayerProps { visible: bool, opacity: f32, locked: bool, alpha_locked: bool,
                        clipping: bool, blend: BlendMode, group: Option<GroupId> }
pub struct StrokeList { chunks: Arc<[Arc<[Stroke]>]> }         // appending copies only the last chunk (<= 256 strokes)
pub struct Stroke { id: StrokeId, tool: StrokeTool, style: StrokeStyle,
                    samples: Arc<[StrokeSample]>, constraints: StrokeConstraints }
pub struct StrokeSample { position: CanvasPoint, pressure: f32, tilt: f32, azimuth: f32, time_ms: u32 }  // time from stroke start
pub struct StrokeStyle { recipe: BrushRecipe, size: f32, opacity: f32, color: Color }
pub enum ArtworkCommand { Layer(LayerCommand), Group(GroupCommand),
                          Reference(ReferenceCommand), Background(BackgroundCommand) }
pub struct Applied { pub artwork: Artwork, pub change: Change }  // Change: None | ActiveLayer | Reference | Content
impl Artwork {
    pub fn apply(&self, cmd: ArtworkCommand) -> Result<Applied, CoreError>;     // one editable_layer() precheck
    pub fn edit_region(&self, edit: RegionEdit) -> Result<Applied, CoreError>;   // commits of selection, fill, transform
    pub fn begin_stroke(&self, style: StrokeStyle, first: StrokeSample) -> Result<StrokeSession, CoreError>;  // on the active layer
    pub fn from_storage(parts: ArtworkParts) -> Result<Self, CoreError>;        // the single full-validation entry
    pub fn to_parts(&self) -> ArtworkParts;                                     // plain data for the store
}
pub struct StrokeSession { base: Artwork, active: ActiveStroke }   // extend / finish / cancel; the active stroke is not in a layer
```

No public mutable setters. Layers come only from `from_storage` or commands; single values (`Stroke`, `LayerGroup`, `LayerImage`) validate themselves on construction. Landed in S2: canvas, layers, active, ids; `LayerProps { visible, opacity, locked }`; `StrokeStyle` without a recipe; `ArtworkCommand::Layer` only; `Change` without `Reference`. `LayerCommand` is `Create` (above the active layer, becomes active), `Delete`, `Reorder`, `Select`, `Rename`, `SetVisible`, `SetOpacity`, `SetLocked`; a command that changes nothing returns `Change::None` and the same version. Landed in S11 (D27): `BrushRecipe { softness, size: Dynamics, opacity: Dynamics, grain: Grain }`, `Dynamics { pressure: Curve, speed: Curve }`, `plain()`; `StrokeStyle` holds an `Arc<BrushRecipe>` and is `Clone`, not `Copy`; `RecipeParts` in `StrokeParts`. There is no separate `constraints` field yet. Landed in S15 (D36): `Layer::edits() -> &[RegionEdit]` (`after`, `mask: RegionMask`, `color`, `alpha_locked`); `RegionMask` (`from_pixels`, `from_runs`, `runs`, bit-packed rows in its rectangle); `Artwork::fill_region(mask, color)` on the active layer instead of a generic `edit_region`; `FillParts` in `LayerParts::fills`; no `LayerImage` yet. ### render

```rust

                  residuals: Mutex<smudge::Engine>, grain: GrainTexture }
pub struct Renderer { core: Arc<Core>, instances: Mutex<Instances>, sinks: Sinks }
pub struct FrameRequest<'a> { artwork: &'a Artwork, active: Option<&'a ActiveStroke>, background: Color,
                              images: ImageSet, view: ViewFrame, consumer: Consumer }
pub struct RegionEvaluator<'a> { core: &'a Core, executor: &'a mut Executor, target: Target<'a> }  // the single evaluation entry
pub enum Target<'a> { Pages(..), Readback(..), Planes(..), SmudgeTiles(..) }
pub enum Batching { Frame, Bounded { visits: u64, invocations: usize, dispatches: usize } }
#[repr(u32)] pub enum Opcode { Segment, EndStroke, EndLayer, Image, BeginScope, EndScope, Fill, Smudge }  // generates the WGSL constants
pub enum RenderError { Admission { what: &'static str, limit: u64 }, Cancelled,
                       MissingImage(AssetId), Device(String), Invalid(&'static str),
                       Timeout { what: &'static str, seconds: u64 } }  // every GPU wait ends within 30 s
```

Evaluation (DECISIONS D16): `Scene::build(&FrameRequest)` flattens visible layers, their strokes and the active stroke into ops in drawing order, each segment op with conservative pixel bounds; `Plan::build(scene, size, regions)` widens the regions to 16 px tiles and lists per tile, in scene order, only the ops that reach it; the compute shader runs one workgroup per tile and one invocation per pixel through that list. `protocol.rs` owns the opcodes and the `Op`, `Tile` and `Params` records and generates their WGSL; a naga-based test checks every offset and size. Landed in S3: `Core { gpu, evaluate }`, `FrameRequest { artwork, active, background }`, `RegionEvaluator { core, target: &CanvasTarget }` (an `Rgba8Unorm` storage texture at canvas size, read back with `CanvasTarget::read`), `PixelRect`, `stroke_region(style, samples)` for the dirty region of new samples, opcodes `Segment`, `EndStroke`, `EndLayer`. Landed in S4 (D17): `RegionEvaluator::new(core, &mut CanvasTarget)`; the target keeps the in-progress stroke's coverage (`R32Float`), the last scene's op buffer and its bindings; opcode `EndActive` and `FRESH`-flagged indices into per-evaluation ops; `ScreenPainter`/`ScreenFrame`/`CanvasPlacement` blit the canvas under the UI; `ScreenTarget` is the harness's offscreen screen. Landed in S6: `changed_regions(before, after)` turns a version switch into the regions callers pass (one per segment of the strokes one version has beyond the other; the whole canvas otherwise). Since S9 the runtime passes it for every change other than committing a stroke (undo, redo, layer edits); layers composite bottom to top, Normal source-over with layer opacity, hidden layers contribute no ops. Landed in S10: `Core::thumbnail(&CanvasTarget, max)` reduces the target on the GPU (box means in integers, `thumbnail.wgsl`) and reads back at most `max` pixels; `thumbnail_size` and `thumbnail_reference` (the exact CPU result) are public. Landed in S11: `stroke.rs` owns stroke geometry (per-sample radius and flow from the recipe and pen speed, `stroke_region(style, samples, from)`); `Op` has 9 operands (segment flows and edge, paint grain) whose named slots and `GRAIN_ONE` are generated into WGSL and checked by the layout test; no grain texture: grain is integer hashing in the shader. Landed in S12: paint ops carry a `Blend` (slot `PAINT_BLEND`, values generated into WGSL): over, atop (Alpha Lock: colour changes only where the layer has alpha) and erase (destination out); zero paint leaves a pixel unchanged in each. `CanvasTarget::pick(core, [x, y])` is render picking: one texel of the target the single evaluation entry filled, the same bytes `read` gives there. `protocol_tests.rs` holds the layout test. Landed in S13: `Core::export(artwork, paper)` evaluates the whole canvas into a target of its own and reads it back; it is called from the runtime's transfer worker. Landed in S14 (D35): `CanvasPlacement { target, origin, size, to_canvas }`: the blit clips to the canvas area, maps each screen pixel through the view's affine rows (a uniform per target) and samples the target bilinearly (`Core::blit_sampler`, no mipmaps); outside the canvas the surround shows. The target and every evaluation region stay in canvas pixels. Landed in S15 (D36): opcode `Fill` (paint operands plus a mask offset in two exact halves, slot `FILL_MASK`), `Scene::masks` uploaded with the scene's ops (`SceneOps`, binding 7), `Core::layer_pixels(artwork, layer)` (one layer alone, premultiplied, transparent elsewhere, through `RegionEvaluator::evaluate_layer` on a target of its own). Landed in S16 (D38): `Op` has 12 operands: a segment adds its paper contacts and a `Tip { Cover, Flat, Bell }` (slots `SEGMENT_CONTACT`, `SEGMENT_TIP`), a paint op its max density (0: covering) and paper (scale, mip level, depth, dust; slots `PAINT_DENSITY`, `PAINT_PAPER`); `shaders/deposit.wgsl` integrates the tips and turns density into coverage through the paper; the target keeps the active stroke's coverage or density and its paper contact in two `R32Float` textures (bindings 6 and 8), taken up at a pixel's first fresh op; `paper.rs` builds the sketch paper's mip chain of rank moments, uploaded once by `EvaluatePipeline` (binding 9); `protocol_wgsl.rs` generates the prelude; `ActiveTrack` redraws both the drawn and the committed end of a stroke revised at its lift. Landed in S17 (D40): `CanvasPlacement::cursor: Option<BrushCursor>`; the blit's view uniform (64 bytes) carries the hover outline and the surround, and the blit draws the outline black or white per pixel against the canvas or surround under it. Landed in S18 (D43): `Op` has 14 operands; paint ops carry a clip (`PAINT_CLIP`, one more than its mask's word offset, 0 none) whose bit multiplies their coverage; `Scene` pushes clip masks into the mask words (shared by consecutive strokes) and keeps the in-progress stroke's (`ActivePlace`, `active_clip`); `CanvasTarget::show_selection` uploads the selection's words (`R32Uint`, binding 3 of the blit) and the view uniform (96 bytes) carries its rectangle and the density for the outline and stripes; `CanvasPlacement::pixels_per_point`. Landed in S20 (D45): `edits.rs` turns region edits into ops: a transform's lift is an erasing `Fill`, its patch opcode `Patch` (inverse placement rows, patch offset at `PATCH_AT`) sampling `Scene::patches` in the patch words (binding 10, reused by the target while the patches stay); a whole-layer transform restarts its layer's ops (`restart`); `changed_regions` costs a dragged transform by its old and new placed rectangles. ### runtime

## 4. Input

Hosts deliver platform events as `runtime::MotionBatch` (phase, buttons, pointers with tool kind and batched samples: position, pressure, tilt, orientation, time); the Android host decodes `MotionEvent` arrays into it in `apps/android/src/motion.rs`. The Android host and the harness feed one normaliser (`runtime/src/normalise.rs`): `MotionBatch` -> `app::InputBatch` (per contact: id, device, phase, samples with position, pressure, tilt, azimuth, timestamp; ranges clamped, times monotonic per contact). egui receives its pointer events from these batches on every platform; no windowing library sits in between. The UI's canvas input (`ui/src/canvas_input.rs`) owns each pen contact that touches down on the canvas itself, outside every control, and hands it to the session as `Intent::Stroke` with its samples mapped through the view into canvas pixels (while the eyedropper is on, any contact, picking). It also follows where the pen hovers over open canvas (for the brush outline) and which fingers are down. Every finger contact goes to `app::Gestures` with whether it touched down on open canvas; what fingers mean (navigation, quick pinch, taps) is decided there, in points, not in the UI's widgets and not in the platform layer; a control that takes a contact resets the trackers. StreamLine lives in the app's stroke intent (S16, D39): the stored samples are the smoothed path. Palm rejection is an app rule too, `app::PalmRejection`, which the runtime applies to every normalised batch before egui or the canvas frame sees it, because a palm must not press buttons either: while a pen contact is down, touches are palms until they lift; a pen landing cancels the touches already down. Platform cancels (`ACTION_CANCEL`, `FLAG_CANCELED` on an up) arrive as `Cancel`; egui gets a cancel as a release far off screen, never a click. The stroke intent drops the zero-pressure lift sample Android reports as the pen leaves the glass. The in-progress stroke travels to the renderer as a separate item and never enters the artwork. Keyboard text reaches egui as IME and key events through `Runtime::text`; the host shows the soft keyboard while `keyboard_wanted` (D26). The back button goes to `Runtime::back`, which the shell answers (canvas to gallery, closing a dialog) or leaves to the system.

## 5. Persistence

- The store owns the format. The `Project` DTO carries an integer schema version; every version has one pure-data migration step and one frozen sample, and the gate round-trips every sample.
- Editor state (current brush, colour, tool parameters) is stored separately from the artwork; when corrupt it falls back to defaults and never blocks opening the artwork.
- Image assets are reclaimed by reference, touching only the artworks this change involves; assets still referenced by session history are never reclaimed.
- Autosave runs on a worker when a stroke finishes and when the editor is left; failure shows a clear message with a retry entry.
- Landed in S7 (DECISIONS D21): `openpaint_store::Library::at(dir)` implements `ProjectStore` on fjall; `records.rs` is schema 1 (keys and values), `codec.rs` the byte reader and writer, `delta.rs` which stroke records a save writes and removes. Android keeps the library in `getFilesDir()/library`; the harness in `artifacts/`. S9 needed no format change (D24). Schema 2 landed in S10 (D25): `catalogue.rs` (entries, thumbnails), `migrate.rs` (the pure step 1 -> 2, applied when a schema-1 library opens), `read.rs` and `write.rs` (one synced batch per call); samples `schema-1.bin` (opens upgraded) and `schema-2.bin` (byte-exact). Schema 3 landed in S11 (D28): recipes in stroke records, the toolbox in `library/editor` (`editor.rs`); `migrate.rs` steps 1 -> 2 -> 3; `schema-3.bin` byte-exact, the older samples open upgraded. Schema 4 landed in S12 (D29): Alpha Lock per layer in the head, a blend byte per stroke, a toolbox of two tools with colour and recent colours; `migrate.rs` steps 1 -> 2 -> 3 -> 4, each seeing the heads and strokes the step before wrote; `schema-4.bin` byte-exact. Schema 5 landed in S15 (D36): a fill count per head layer and one record per fill (`fills.rs`, runs as LEB128 varints); `migrate.rs` adds step 4 -> 5; `schema-5.bin` byte-exact. Schema 6 landed in S16 (D38, D39): a deposit after each recipe's grain, a StreamLine per toolbox brush; `migrate_6.rs` holds step 5 -> 6 (the library carries the toolbox record from step to step); `schema-6.bin` byte-exact. Schema 7 landed in S18 (D43): a clip after each stroke's samples; the stroke codec moved to `strokes.rs`, the mask codec is shared in `fills.rs`; `migrate_7.rs` holds step 6 -> 7; `schema-7.bin` byte-exact. Schema 8 landed in S20 (D45): edit records (`fills.rs`) start with a kind, a transform's patch is a PNG at the record's end; `migrate_8.rs` holds step 7 -> 8 (the only step that reads fill records); `schema-8.bin` byte-exact. Schema 9 landed in S21 (D46): stroke blends 3 and 4 (smudge), the toolbox's smudge choice; `migrate_9.rs` holds step 8 -> 9; `schema-9.bin` byte-exact. Schema 10 landed in S23 (D49): clipping, blend and group per head layer, a group table at the head's end; `migrate_10.rs` holds step 9 -> 10; `schema-10.bin` byte-exact. Schema 11 landed in S24 (D51): a mask per head layer and the target at the head's end, mask records under `mask_slot(layer)` (`delta::contents` lists every slot); `migrate_11.rs` holds step 10 -> 11; `schema-11.bin` byte-exact. S26 needed no format change: an inserted picture is a whole-layer transform record (kind 1, no lift, the picture as its PNG patch) on its new layer; `image_file.rs::open_picture` decodes, turns upright, premultiplies and reduces it.
- Colour (S27, D53): inside the app every pixel is sRGB-encoded. Colour management lives only at the file boundary, `store/src/colour.rs` on moxcms: `decode_image` (insert and reference) converts a file's embedded RGB ICC profile (PNG `iCCP`, JPEG APP2) into sRGB on straight RGBA8, keeps untagged and sRGB files bit for bit, takes unusable, grey and CMYK profiles as sRGB; `encode_image` embeds the fixed sRGB profile `store/assets/srgb.icc` in every PNG and JPEG export. The window surface is configured in `SurfaceColorSpace::Srgb` (`render/src/surface.rs`, `Surface::report` logs the offered formats and colour spaces at attach).

## 6. Brushes and rendering

- A brush is a declarative recipe (TOML): shape, size and opacity curves over pressure and speed, grain, dynamics. Rendering evaluates continuously per pixel along the stroke; there is no dab/stamp engine, no node graph, no shader plugin.
- A stroke stores a recipe snapshot; reopening an artwork never silently applies a renamed brush's new behaviour.
- Landed in S11 (D27): stages softness, size and opacity dynamics (pressure x speed curves) and grain; "dynamics" beyond pressure and speed (tilt, azimuth) are not stages yet. Built-ins Pencil, Ink Pen (= the plain round brush, the default) and Soft Brush.
- Landed in S16 (D38): the deposit stage. Ink Pen covers (crossings never darken); Pencil accumulates graphite under a flat tip on the canvas-fixed sketch paper (draweave's tuned values); Soft Brush accumulates under a bell. Density is laid per radius travelled, capped by the stroke's opacity.
- Landed in S21 (D46): the smudge, a third tool with the same recipes: contacts along the path carry the layer's colour; evaluated once per stroke into a residual, not per pixel (the one exception to "no dab engine", because a smudge reads its neighbours).
- Export always uses native precision; the screen shows a fast result first and swaps in the refined one when background work completes, without changing extent or strength.

## 7. Errors

`CoreError` (artwork semantics), `AppError` (modes and flows), `PortError` (external capabilities), `RenderError`, `RuntimeError`. The platform layer translates them into user-facing messages; `String` appears only in JNI, system APIs and xtask.

## 9. Enforced rules

`cargo repo-check` (`xtask/src/check/rules.rs`): .rs files at most 400 lines; dependency direction per the table in section 2; purity tokens per table (core never mentions serde; devtools never touches `std::fs`); egui in render only under adapter; no cargo features in product crates; crate roots carry `#![forbid(unsafe_code)]` (android excepted); markdown limited to six files plus the archive; no script files; no CRLF. clippy: functions at most 60 lines, no `todo!` / `unimplemented!` / `dbg!`, warnings are errors; the gate also runs clippy on `openpaint-android` for `aarch64-linux-android`, the only build that compiles its JNI code.

## 10. UI conventions

The UI is designed from the user inward (AGENTS.md, "Design from the user inward"). These are the fixed defaults.

- The default interaction model is Procreate's. Before building a feature, read its Procreate Handbook page (entry point, gesture, feedback) and follow it. Deviate only for Android tablet hardware or on the author's instruction. Never copy icons, colours or assets.
- Layout skeleton (S17, D40): the canvas shows on the whole screen; the controls float over it as ink-outlined `island`s and nothing spans the width: Gallery and Actions at the top left, Brush, Eraser, Layers and the colour at the top right, the side bar at the left edge (can be mirrored for left-handed use). The canvas fits under the 48-point top band (`CanvasArea { screen, fit }`), so at fit the top islands lie on the desk. Panels are popovers over the canvas and close with one tap outside. A modal appears only before a destructive action. What comes and goes is a `pill` in the top band: notices left of the right island, the fill bar and the view's zoom in its middle.
- Popovers (S9, `components::popover`): anchored under the right island (Actions under the left one), growing out of their island button (S19), usable from the frame they open. A contact starting on a popover or an island never reaches the canvas (`CanvasInput::route` takes the covers); a contact landing on the canvas outside closes it, and a pen stroke there draws. Components: `icon_button`, `icon_toggle` (an ink ring while its panel is open), `text_button` (a command: a bare word in ink, the press wash under the hand; S25), `choices` (a group of mutually exclusive items in one container owning their one mark: `text_choice` / `text_choice_wide`, a word whose chosen one carries the ink pill, the icon ring's line round the word; `icon_choice`, the tools' ring; G3 follow-ups), `divider` (a faint upright line between a bar's choice and its commands, or a pill's message and its action), `hint` (a quieter line saying what something does), `command_row` (a leading icon and words in ink: Add Mask), `list_row` (chosen row outlined in ink, an icon button at its end), `slider` (value and `settled`), `notice`, `popover`, `island`, `pill`; since S10 `dialog` (over a veiled screen, centred or under the islands; a tap outside cancels), `text_field`, `artwork_card` (the thumbnail as a sheet on the desk).
- Side bar and brushes (S11, S17): `components::side_panel` floats at the left edge centred on the fit area (one constant mirrors it), holding two `side_slider`s and undo and redo; contacts starting on it never reach the canvas. Each slider says what it sets by end marks (a small and a large dot for size, a faint and a solid disc for opacity) and, under the hovering pen, its name; while held, a bubble beside the bar shows the value with the brush's circle at its real size on the canvas or a swatch at that opacity. The brush panel is a popover of `brush_row`s with previews painted by the evaluator (black on white, shown as ink).
- Tools and colour (S12, S21): the right island holds, left to right, Brush, Smudge, Eraser, Layers and the colour button (a `swatch` of the current colour; Procreate's order); the current tool's button carries the ink ring and opens its brush panel, the other tool's button switches tools. The colour popover holds a `color_wheel` (hue ring, saturation and value square) and a row of recent swatches. The eyedropper is an `icon_toggle` between the side bar's sliders. Alpha Lock is a `switch_row` in the layer panel's footer. One panel at a time.
- Actions and reference (S13, D41, S26): Actions (a spanner) follows Gallery in the left island and opens a popover of `menu_row`s and a `switch_row` (sections Add: Insert image…; Share; Canvas); an inserted picture comes back as a transform on its new layer, so it uses the transform's frame and bar; progress and results show as a `status` or `notice` in a pill; the reference picture is a `floating` window with no title bar: a tap toggles a slim bar (grip, ×) and a corner resize mark, one finger pans and two pinch the picture (`app::PictureGestures`). Its contacts are routed from the raw batches before the canvas (`reference_touch.rs`) and never reach the canvas.

Intuitive (a first-day user needs no instructions) and restrained (UI appears when needed; cues over controls); hidden shortcuts only duplicate a visible control.
- Every feature ships with a discoverable entry, visible feedback for success, failure and cancel, undo for anything that changes the artwork, and state that survives reopen. Missing any of these means the slice is not done.
- Checklist that harness screenshots and scenarios must show: the most frequent actions (brush, size, opacity, colour, undo, layer) within two taps; hit targets at least 48 points at tablet density (the icon is not the hit area); nothing covers the canvas while a stroke is possible; feedback within one frame; the same component for the same job everywhere.
- Motion (D44). Motion only explains: where something comes from or goes, what changed, that input arrived. Never on the drawing path (strokes, canvas navigation, slider drags follow the contact 1:1); interruptible, never blocks input, retargets instead of queueing; critically damped unless a gesture released momentum; open about 0.4 s or less, close faster; elapsed time, never per frame. Four patterns, built into the shared components; screens only declare state and never animate by hand; a new pattern needs a decision:
  - emerge / retract: a surface grows from its source and returns to it (panels from their island button, dialogs, notices, the loupe, the reference window, a gallery card into the canvas);
  - fade through: unrelated content in one place (switching panels: the old one retracts into its own button, the tapped one grows from its button and finishes last);
  - settle: things that move, appear or leave make room (layer rows, quick pinch to fit, the chosen mark of a `choices` group sliding and resizing to the item chosen, retargeting mid-slide, never across groups or islands; in place when the group first shows);
  - acknowledge: a state changes in place (a toggle's ink ring, a mark appearing or going with no choice before or after it, switches, swatches, the selection hatch).
  No motion for canvas content changes (undo included), the ColorDrop dot, slider drags or the hover outline.
  Landed in S19: `design/motion.rs` (`Spring`, `Feel`, presets `OPEN`, `CLOSE`, `RETRACT`, `SETTLE`, `ACKNOWLEDGE`, the switch delay, pour and reveal); springs live in egui's memory and step by egui's input time (`components::animate`, `settle`). `components::chrome` keeps every surface's `Growth` (`surface.rs`): a surface only declares each pass whether it is open and its `Source` (`Button` on an island, `Rect`, `Within` its own end); content is laid out at its finished place (taps hit the final state; a closing panel's area is not interactable), and `chrome_frame.rs` clips its shapes to the moving shape and fades it in. Islands (`island`) and the panels growing out of them (`popover`, `Opener`) are one SDF silhouette drawn by `render::chrome_shape` (`adapter/chrome.rs`, `shaders/chrome.wgsl`; one paint callback per island's reach, all sharing one uniform) in a Foreground layer under the islands' and panels' content; pills, dialogs, the loupe and the reference window are separate paper (`paper.rs`) that retracts with no content once no longer shown. A screen switch drops what the old screen showed. The view settles through `ViewSettle` (display only; `ViewMapping::{placed, toward}`; any canvas contact stops it); the gallery card and the canvas through `carry.rs`. The runtime's `FrameClock` is real time, or `Runtime::fix_clock` in the harness; `Runtime::moving`.
- Lessons carried over from draweave (D33; each was a failed author check or a fix there):
  - Controls have three states: available; unavailable (greyed, nothing to act on); temporarily blocked (normal look and hit area, the action is refused at the intent). An active stroke or a captured panel only ever blocks temporarily; nothing greys out or flickers per stroke.
  - Any control that takes a contact resets the gesture trackers, so a button tap never lingers as a canvas gesture. Gestures read raw touch geometry including the release positions (Android batches the last move with the up).
  - A tap outside a panel closes it and consumes only that contact; the next contact draws. The tap that opens a panel never dismisses it. Panels float and never shrink the canvas; they size to their content.
  - Sliders say what they set (a label or end icons plus the live value), show a preview while dragging (size: a circle at the real size; opacity: a swatch at that alpha), restore the original value on cancel or focus loss, and belong to one contact at a time.
  - The pen's hover shows the brush outline at full size, a 1-point line contrasting with the canvas under it, hidden over controls and during multi-touch. The eyedropper commits the last valid preview, not where the contact drifted on release.
  - Animations advance by elapsed time, never per frame. Notices are brief; quiet success, persistent failure. Every icon-only button has an accessible name and a hover label; new concepts and destructive actions use icon and text.
- Who decides: details are the agent's. The author judges on the tablet at stage exits and sends one-line change requests. Ask the author in advance only for a deviation from Procreate's mental model, for anything the hand touches continuously (side bar position, gesture mapping, pen buttons) or for anything that changes the persistent format.

# Architecture

OpenPaint is an Android-first, stylus-first 2D painting app whose goal is to take an illustration from sketch to delivery on one tablet. Android is the only product host. On the development machine a headless harness renders offscreen, replays recorded input and runs scenarios; there is no desktop window and no desktop product.

This page is the design contract: how modules are cut, which way dependencies point, what the core types look like, how threads and errors are handled. When code and this page disagree, change the code or change this page and record a decision; never keep both.

## 1. Principles

1. One concept has one definition and one owner, and the owner is a module, not just a crate. Mutable/immutable, intent/command and persistent/session forms are never kept twice.
2. The artwork is an immutable value. An edit produces a new version, history stores versions, undo switches versions (D08).
3. Product crates have no `cfg(feature)`. Diagnostics, experiments and automation probes live in separate crates and are assembled only by composition roots (D10).
4. The renderer depends on core only. GPU state belongs to the renderer's own `Core`, never to the UI framework. One render core, the raster core, draws every scene for every reader (D92, D93); the GPU protocol is defined once in Rust, injected into WGSL and proven by layout tests.
5. Strokes and operation records are the truth; every pixel is a derived, discardable cache.
6. Pay per change: saving, history budgets and projections touch only the data a change involves; the UI thread never does work proportional to artwork size.
7. Errors are types. `String` errors are allowed only in JNI, at system boundaries and in xtask.
8. One user action has one product path: no double writes, no simple/advanced variants, no silent fallbacks, no modules or abstractions reserved for features not yet accepted.
9. Files at most 400 lines, functions at most 60 lines, tool-enforced; `lib.rs` holds only `mod` and `pub use`.

Dependencies only point down (`A <- B` means B depends on A):

```text
core <- app <- store
core <- app <- ui <- runtime <- {harness, android}
core <- render <- ui
core <- raster <- runtime
practice, app <- practice-app <- {practice-store, practice-ui, runtime}; ui, practice <- practice-ui <- runtime; practice <- runtime
practice, store <- practice-store <- {runtime, devtools, harness, android}
store, render <- runtime
runtime <- devtools <- harness
sheet <- {harness, tools/packs}; practice, practice-store, app, store <- tools/packs
```

A new crate is registered in `LAYERS` in `xtask/src/check/rules.rs` first (D02). The app's version is `[workspace.package] version` in the root manifest; `xtask/src/version.rs` hands it to Gradle with the store's `FORMAT` as build metadata and a version code, and the runtime hands the same two to the shell (`Shell::set_version`), which shows them as Actions' last line in the language shown (D79).

## 3. Core types

### core


No public mutable setters. Layers come only from `from_storage` (the single full-validation entry, `ArtworkParts`, `parts*.rs`) or commands; `to_parts` gives plain data for the store. A command that changes nothing returns `Change::None` and the same version. Ids are never reused; limits (`MAX_LAYERS`, `MAX_STROKE_SAMPLES`, `MAX_CANVAS_SIDE`, `MAX_NESTING`, `MAX_STAMPS`) are public constants. The modules:

- Layers and groups: `layer.rs`, `layer_command.rs` (`Create`, `Delete`, `Select`, `Rename`, `Move { layer, by }`, `Duplicate`, `MergeDown`, visibility, opacity, lock, Alpha Lock, clipping, blend), `layer_moves.rs` (`stepped`, `layer_places`: one step's rule into and out of groups), `group.rs`, `group_command.rs`, `blend.rs`, `mask.rs` and `mask_command.rs` (D51), `merge.rs` (`Artwork::mergeable -> Result<(), Unmergeable>`, D66).
- Strokes: `stroke.rs`, `session.rs` (`StrokeSession`: extend, `revise` its end, `reshape` it whole, finish, cancel; the active stroke is not in a layer), `stroke_list.rs`.
- Recipes (D74): `brush.rs` (`BrushRecipe`, `Dynamics { pressure, speed, tilt }`, `Curve`), `deposit.rs` (`Cover` or `Accumulate`, paper; D38), `taper.rs`, `shape.rs` (`Shape`, `Stamp`, `ShapeTexture`, `jitter`).
- Records: `fill.rs` (`FillEdit`, `Artwork::fill_region`), `clear.rs`, `transform.rs` (`Placement`, `Patch`, `place_region`, `transform_region`; D57), `adjust.rs` and `tone.rs` (`Adjustment`, `ToneCurve`), `filter.rs` (`Blur`, `Sharpen`; D59), `nested.rs` (`NestedLayer`), `copy.rs` (`Copied`, `copied`, `paste`, `cut`; D67), `region.rs` and `mask_ops.rs` (`RegionMask`: polygon, union, intersect, inverted, whole; D43).

## 4. Input

Hosts deliver platform events as `runtime::MotionBatch` (phase, buttons, pointers with tool kind and batched samples: position, pressure, tilt, orientation, time); the Android host decodes `MotionEvent` arrays into it in `apps/android/src/motion.rs`. The Android host and the harness feed one normaliser (`runtime/src/normalise.rs`): `MotionBatch` -> `app::InputBatch` (per contact: id, device, phase, samples; ranges clamped, times monotonic per contact). egui receives its pointer events from these batches; no windowing library sits in between.
Palm rejection (`app::PalmRejection`) applies to every batch before egui or the canvas sees it: while a pen contact is down, touches are palms until they lift; a pen landing cancels the touches already down. The UI's canvas input (`ui/src/canvas_input.rs`) owns each pen contact that touches down on open canvas and hands it to the session as `Intent::Stroke` mapped through the view into canvas pixels (any contact, picking, while the eyedropper is on); it follows the hovering pen for the brush outline.
Finger contacts go to `app::Gestures`, which decides in points what they mean (navigation, quick pinch, taps, the three-finger swipe). Contacts on the reference window, a ColorDrop drag, a snapped shape's handles, the guide's centre, the transform frame and the brush strip are routed from the raw batches before the canvas. Platform cancels arrive as `Cancel`; egui gets a cancel as a release far off screen. The stroke intent drops Android's zero-pressure lift sample. The pen's side buttons are read from every pen event's button state into `InputBatch::pen` and handed to `app::ButtonTracker` before and after each batch's contacts (D70). StreamLine lives in the stroke intent; the stored samples are the smoothed path. Keyboard text reaches egui as IME and key events through `Runtime::text`; the host shows the soft keyboard while `keyboard_wanted` (the host is the text editor, no `EditText`); the back button goes to `Runtime::back`.

## 5. Persistence

- The store owns the format: one storage format, `openpaint_store::FORMAT` 1 (D95), for the library, OpenPaint files and kept versions. A library or file of another format is refused as `PortError::OtherFormat` before anything is written.
- The library (D77): `Library::at(dir)` implements `ProjectStore` on fjall, keyspaces `library` and `projects`; Android keeps it in `getFilesDir()/library`, the harness in `artifacts/`. `records.rs` the keys and the head, `strokes.rs` and `shapes.rs` a stroke, `edits.rs` an edit record (`write_optional_mask`; `adjusts.rs`, `nested.rs`), `catalogue.rs` entries and thumbnails, `editor.rs` and `editor_library.rs` the toolbox (the language a byte at its end once chosen, D100), `codec.rs` the byte reader and writer, `delta.rs` which records a save writes and removes, `read.rs` and `write.rs` the calls, `batch.rs` the one atomic batch per call, `library.rs` (`prepare` checks the format, marking an empty database; no upgrade path, S116). Every save writes a new random save id into the head.
- Record spaces (`spaces.rs`, D112): a mode's records in `library` under keys of its byte (`app::Space`; the store's own initials `a c e f l n v` refused), bytes it never reads: `records` (under a prefix), `put_records`, `create_owned` (a project, the open one, and its records, one batch), `remove_owned`, `artwork` (read only); `list` lists every project.

- Practice (`openpaint-practice-store`, D98, D99, D112): `records.rs`, a sheet's record under `['p'][sheet u64]` (tag 0x53: canvas, started, purpose (3 a test's), spans, lessons with how picked, the exercise in hand and each as laid; outcome codes 1 to 3, judge 1 app 2 eye) and a lesson's givens under `['g'][canvas u64][lesson u16]` (`givens/`); read only in this shape, every field required, an unknown tag, kind, metric or outcome refused; `stored.rs`: `sheets` (one unreadable left out, logged), `start` (project, sheet and givens in one batch), `append` (sheet and its new givens, one batch), `save` (the sheet), `remove` (record, givens and project at once), `trim` (End's cut sheet with a removed lesson's givens, one write, `ProjectStore::rewrite_records`); `blocks.rs` the Pomodoro's records in space `t` (`['t']['s']` settings, `['t']['u']` the block under way, a completed block each, `save_timer`, D117). - Packs (D101, D103, in practice-store): `pack.rs` (the file: magic, `PACK_FORMAT` 4, a checked head with each item's credit, outline, value masses (runs) and colour areas (colours, runs), each or none, pictures; a pack of another format is `OtherFormat`, refused on import and left out of the list), `pack_picture.rs` (decoded, at most 2048, PNG if transparent else JPEG; `shown_picture` 1024 for the screen, `thumbnail_picture` for the options) and `packs.rs` (`Packs::at(dir)`: `<dir>/<id>.pack` beside the library, import checked whole and renamed into place (never the personal pack), `add_picture` at a tier writing the personal pack whole with the new one last (its id the file's CRC-32), `remove_picture`, `set_tier`, `list` from heads, `picture(&ItemRef)` by offset and check sum); a non-pack file is `Corrupt { what: "practice pack" }`.

- Images (`colour.rs`, `image_file.rs`, `export_file.rs`; D53, D55): decoding with colour conversion into sRGB; `ImageEncoder` takes bands of rows (PNG streamed, JPEG at the end) and embeds the sRGB profile.

- Tests: frozen samples, `store/tests/samples/format-1.bin` (`tests/format.rs`, `tests/sample/`, every record kind) and practice-store's `areas-records.bin` (sheets and givens through the record spaces); the store's unit tests fail its n-th write through a test-only hook (leaving, a save cut at every byte, a project created or removed with its record).

## 6. Brushes and rendering

- A brush is a declarative recipe (TOML in `app/brushes/`; the practice pens' own in `app/pens/` (S100), their hard tip Hard Paint's file (S104)): softness, size and opacity curves over pressure, speed and tilt, grain, deposit, taper, shape (D74). Rendering draws per pixel along the curve through the stroke's knots (D71), its stamps too; there is no node graph or shader plugin. A stroke stores its recipe's snapshot and its seed; reopening never applies a brush's later edits.
- The deposit (D38): covering strokes keep the largest coverage; accumulating ones lay density (the Pencil on canvas-fixed sketch paper, the Soft Brush under a bell). Shapes: stamps belong to the span whose length range holds them, textures from `cargo shape-assets` (`xtask/src/shapes.rs`).
- The smudge reads its neighbours, so it is drawn once per stroke into a residual (D46); Gaussian Blur and Sharpen likewise into arena blocks (D59). Everything else is drawn per pixel by the raster core.
- Exports draw at their scale (D55), the 1x export is the canvas pixel for pixel, a tier tile is its export (D93).

## 7. Errors

`CoreError` (artwork semantics), `AppError` (modes and flows, refusals such as `LayerRefusal`), `PortError` (external capabilities), `RenderError`, `RuntimeError`. The platform layer translates them into user-facing messages; `String` appears only in JNI, system APIs and xtask.

Storage failures are contained per call and per artwork (D77): a failed write leaves the library as before the call (the save's notice with Retry; a failed kept version is only logged), and a record that cannot be read fails only that artwork's opening ("Couldn't open this artwork"), never the library. A library or file of another format is `PortError::OtherFormat` (D95).

A lost GPU device is not an error the user sees (D96): wgpu's lost callback, out of memory or a driver failure mark the `Core` lost, and a frame that finds it so, or fails with `RenderError::Device` or `Timeout`, makes the renderer again on a new device (`runtime/src/recover.rs`) before it goes on; a job running on a worker at the loss fails as any GPU failure does; app state is never touched.

Test fixtures live in each crate's `tests/` or in devtools, never in the product API. Each GPU test binary opens one device. Tests drive time by the runtime's held clock (`fix_clock`, the `Hand`'s): motion, input, idle and recency follow it, never the wall clock, which only guards against a hang (two minutes). The pure `openpaint-practice` is optimised in dev builds too.

Scenarios (D19, D48): `tests/scenarios/<name>.json` holds a walk-through (text), the screen size and density, the host's `system_language` (English unless `"chinese"`, D100), `start` (a blank canvas, or `"home"` the first launch, D116) and the steps that replay it: `lesson` (`lesson.rs`: `{ "skill": "line", "level": 1 }`, `"first"`, `"next"` the home's main control), `host` (`host.rs`: the chimes played and the screen kept on), `tap`, `drag`, `stroke` (with `lift`, `palm`, `sparse`, `pen` buttons or the eraser end, `hold_ms`, `tilt`, `azimuth`), `press` (`[x, y, ms]` keys, `before_lift`, `interrupted` by `detach` or `leave`), `touch` (1 to 5 fingers), `hover`, `type` (a newline presses Enter), `back`, `wait`, `later` (minutes on at once, the app untouched or `hidden`; the held clock, a Pomodoro's too), `restart`, `storage_fails` / `storage_works`, `system` (a fixture picture, the test pack or the test frames (S99: shapes not square) drawn in `devtools/src/test_pack.rs`, or the test compositions painted in `test_compositions.rs`, or the test crops of known areas in `test_crops.rs` (S101), for a picker), `lose_device`, `checkpoint` (canvas hash), `view`, `exported`, `preview`, `expect` (controls that must and must not show) and `screenshot`.
A spot is a control's name (`name #n` when shared), `{ on, fraction, offset }`, or window pixels on the canvas only; pixels on a control fail the run with the name to write. `openpaint_devtools::run` turns gestures into `MotionBatch`es and drives `Runtime` offscreen on a library directory and a packs directory beside it; the runner holds the clock (batch times, then 16 ms a frame), lets motion settle before steps that look (a `screenshot` with `after_ms` catches a motion mid-way), fixes every stroke's seed and opens one device with an 8-bit screen. `cargo scenario <name>` writes PNGs and failure diffs under `artifacts/scenarios/<name>/`; the gate runs `smoke`.

Device chores are `cargo device-*` (`xtask/src/device/`: adb with explicit arguments, never a host shell; `DeviceError`): `device-backup`, `device-restore` (the library and the practice packs as found saved first, tar members compared byte for byte, a pack kept after the backup removed by its path; `library.rs`, `tar.rs`), `device-check`, `device-input` (one injected gesture through the debug build's `GestureInstrumentation`, taps by control name through `DebugControls`, `state.rs`, `open-file` (a pushed `.pack` imported too), `practice-test` (`practice_test.rs`: a test lesson or colour copy, its name kept in `artifacts/device/practice-test`), `bench`, `home`, `gradient`, `lose-device`),
`device-clean`, `device-screens` (`screens.rs`: the tablet's newest screenshots pulled and listed, nothing changed), `device-push` (`--download`: into `/sdcard/Download/` for the author), `device-info` (read-only `getprop` and `dumpsys`, `--watch`), `device-idle` (`idle.rs`: the screen, the app in front and the minutes since the last touch, pen or key from `dumpsys power`; exit 0 when untouched 10 minutes or more or the screen is off, every routine starting with it; the agents' own injected gestures count as touches), `device-smoke` (`smoke.rs`, `smoke_checks.rs`: a fixed list of steps on a test artwork it makes and deletes) and `device-reset` (`reset.rs`: `pm clear`, refused without a backup written the same UTC day).

## 9. Enforced rules

`cargo repo-check` (`xtask/src/check/`, over tracked and new unignored files): .rs files at most 400 lines, a folder at most 64 of them (`folders.rs`: `crates/render/src`, past it when the rule came, held at its count, which may only go down); dependency direction per section 2; purity tokens per crate (core never mentions serde; devtools never touches `std::fs`; core, raster, render, app, the store and the ui never name practice, comments included, D112); egui in render only under `adapter/`; no cargo features in product crates; crate roots carry `#![forbid(unsafe_code)]` (android and the harness's allocator excepted); markdown only the four documents (within their lines and characters, 1,500 a line: `lengths.rs`), README, AGENTS.md and the archive; no script files; no CRLF; `tools/packs` with the root's lints, its rustfmt and clippy run (`tools.rs`); under `crates/ui/src/` and `crates/practice-ui/src/` outside each one's `text/` and tests no literal reading as words (a capital, then a small letter) and none handed to `Words::made` or `named` (`words.rs`, D100); outside `crates/practice/src/kinds/` no match on `Kind`'s variants in product code, nowhere an enum `Family`, `Original`, `Tools` or `Picks` or its variant (`kinds.rs`, S109 to S123). clippy: functions at most 60 lines, no `todo!` / `unimplemented!` / `dbg!`, warnings are errors; a justified exception is `#[expect(lint, reason = "...")]`, never `#[allow]`.

## 10. UI conventions

The UI is designed from the user inward (AGENTS.md, "Design from the user inward"). These are the fixed defaults.

- The default interaction model is Procreate's. Before building a feature, read its Procreate Handbook page (entry point, gesture, feedback) and follow it. Deviate only for Android tablet hardware or on the author's instruction. Never copy icons, colours or assets.
- Layout skeleton (D40): the canvas shows on the whole screen; the controls float over it as ink-outlined `island`s and nothing spans the width: Home, Actions, Adjustments, Selection and Transform at the top left; Brush, Smudge, Eraser, Layers and the colour at the top right; the side bar (size and opacity sliders, the eyedropper, undo and redo) at the left edge. The canvas fits under the 48-point top band (`CanvasArea { screen, fit }`). Panels are popovers over the canvas, one at a time, and close with one tap outside. A modal appears only before a destructive action. What comes and goes is a `pill` in the top band: notices left of the right island; the fill, selection, transform, shape and copy bars and the view's zoom in its middle.
- Components (`ui/src/components/`): `island`, `popover` (grown out of its island button, usable from the frame it opens), `icon_button`, `icon_toggle`, `text_button` (a command: a bare word in ink with the press wash; `pill_button` in a pill), `choices` (a group of mutually exclusive items owning their one mark: `text_choice`, `text_choice_wide`, `icon_choice`; `word_columns` lays words out in two columns with a `Lead`), `divider`, `hint` (a quieter line), `command_row`, `menu_row`, `label_row`, `panel_heading` / `panel_heading_with`, `list_row` (the chosen row outlined, an icon at its end; `picture_row`: a picture small beside its title and a line; `row_drag.rs` carries a held row), `slider`, `side_slider`, `setting_slider`, `switch_row`, `swatch`, `color_wheel` (with `color_compare`, two colours as a picture), `curve_editor`, `preview_strip`, `brush_row`, `notice`, `status`, `pill`, `dialog` (`dialog_of_width` for a page of two columns, `naming_dialog` with `Naming`, `delete_dialog`), `text_field`, `artwork_card`, `card` (`card_text`, `card_columns`, `card_step`), `wheel_picture` (a demonstration's small wheel), `floating`, `loupe`, `fill_bar`, `view_status`, `canvas_frame`, `picture`, `paper`, `chrome::declare`. Taps go out through `taps.rs` (`push_once`, `push_brush`); `Place::middle_unless` puts a bar in the band's middle unless another holds it. Every shared component registers its name and rectangle in the `ControlMap` (`components/controls.rs`).
- Words (D100): every word shown is a `Text` of a table: the ui's in `ui/src/text/` (`common`, `canvas`, `layers`, `brushes`, `colour`, `gallery`, `notices`; `texts!`, `Text`, `Words`, `language`, `RETIRED` exported), practice's in `practice-ui/src/text/` (`sheet`, `colour`, `options`, `perspective`, `points`, `solids`, `objects`, `division`, `book`, `course` (the path, a lesson's names, results and end), `pomodoro`, `names`, `kinds/` a file a kind: its names, How cards, one line each in its `KINDS`, found by key, S109b; `says` a card's `Say` keys); English and Chinese side by side, functions for words with numbers; `names.rs` shows the names the app and a mode give (`Names`, `Shell::set_names`) in the language. Components take `Words` and show them in the pass's language and names, which the shell sets on the context; the control map gets the English. A card's Chinese paragraph is line-broken by the UI (`card.rs`).
- The theme is defined once in `ui/src/design/` (D40): `palette.rs` (paper, desk, ink, the deeper active ink, outline weight; practice's never-chrome colours, the checks' red, a constructed exercise's printed grey, the book's pencil and vermilion, in `practice-ui/src/palette.rs`), `paint.rs` (`Outline`, the shape of a control's mark: the icon ring, the same ring as a pill round a word, the row outline; the press wash fills exactly that outline, never the 48-point hit area), `icons.rs` (self-drawn ink-line icons in one 1.5-point weight behind a semantic `Icon`), `fonts.rs`, `motion.rs`, an 8-point spacing scale, one type scale (18-point body). Screens compose components and never style widgets inline. - Every feature ships with a discoverable entry, visible feedback for success, failure and cancel, undo for anything that changes the artwork, and state that survives reopen. Missing any of these means the slice is not done.
- Checklist that harness screenshots and scenarios must show: the most frequent actions (brush, size, opacity, colour, undo, layer) within two taps; hit targets at least 48 points at tablet density; nothing covers the canvas while a stroke is possible; feedback within one frame; the same component for the same job everywhere.
- Motion (D44): motion only explains (where something comes from or goes, what changed, that input arrived); never on the drawing path (strokes, navigation, slider drags follow the contact 1:1); interruptible, retargets instead of queueing; critically damped; about 0.4 s to open, faster to close; elapsed time on the runtime's frame clock. Four patterns, built into the shared components (`components::chrome`, `surface.rs`, `chrome_frame.rs`, `carry.rs`, `view_settle.rs`): emerge / retract (panels from their island button sharing one SDF ink outline with the island, dialogs, notices, the loupe, the reference window, a card into the canvas); fade through (switching panels); settle (layer rows, a dragged row's neighbours, quick pinch to fit, a `choices` group's mark sliding to the item chosen, never across groups); acknowledge (a toggle's ring, switches, swatches). No motion for canvas content changes, the ColorDrop dot, slider drags or the hover outline. Taps always reach the final layout at once.
- Lessons carried over from draweave: controls have three states (available; unavailable, greyed; temporarily blocked, normal look, refused at the intent: an active stroke only ever blocks temporarily); any control that takes a contact resets the gesture trackers; gestures read raw touch geometry including release positions; a tap outside a panel closes it and consumes only that contact; the tap that opens a panel never dismisses it; panels never shrink the canvas; sliders say what they set, preview while dragging and belong to one contact; the pen's hover shows the brush outline at full size, hidden over controls and during multi-touch; the eyedropper commits the last valid preview; notices are brief, success quiet, failure persistent; every icon-only button has an accessible name and a hover label.
- Who decides: details are the agent's. The author judges on the tablet at stage exits. Ask the author in advance only for a deviation from Procreate's mental model, for anything the hand touches continuously (side bar position, gesture mapping, pen buttons) or for anything that changes the persistent format.

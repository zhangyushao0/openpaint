# Roadmap

## Product definition

An Android-first, stylus-first 2D painting app that completes, on one tablet: sketch -> inking -> layered flat colour -> smudging and shaping -> selection revisions -> masks and colour overlays -> adjustments and finishing -> export -> resume after interruption. Interaction follows the user's mental model from Procreate by default, adapted to Android tablets; no copying of look, icons or assets.

Stage exits are judged on representative artworks made by the author on the tablet: W1 inking and flat colour, W2 painterly shading, W3 complex composition revision, W4 edit, restore and deliver.

Non-goals (G0 to G7): network, accounts, cloud sync, community, animation, 3D, multi-platform, plugin systems, a desktop product or desktop window of any kind.

## Rules

- A slice is a vertical cut one session can finish, verify and roll back on its own. Slices run in numbered order; no skipping.
- Every slice states its goal, the crates involved and done criteria. Done criteria are executable or observable, never "better".
- A slice that changes what the user sees or does begins with its walk-through written as the user and ends with that walk-through as a passing scenario plus a screenshot review (AGENTS.md, "Design from the user inward").
- The dev-machine loop is the harness (`apps/harness`): offscreen rendering, replay, scenarios, PNG and hash output. "Seeing" a result means reading its PNG. Real input and pen feel exist only on the tablet.
- When a slice is done: rewrite STATUS, move the slice to "Done" at the end of this file (one line), add a DECISIONS entry only if a decision was made.
- Stage-exit items that need the author on the tablet are recorded as `pass` / `fail` / `not_run`; a dev-machine result never substitutes.
- Findings outside the slice go under "Candidates"; they are not fixed in passing.
- Performance (D47): a slice is fluid at its feature's default sizes on the tablet; other numbers are measured and recorded, never done criteria; chasing them is G7 (named G5 in decisions before 2026-10-04).

## G6 Brushes

Direction (author, 2026-10-04 and 2026-10-09): think from the digital painter and the finished picture, never from imitating traditional media (no "oil" or "watercolour" brushes); the pencil keeps its cultural feel (grain, pressure) without simulating graphite inside. Procreate's Brush Studio is the mental model, with only the dozen settings the engine really has. Strokes stay the truth: shapes, scatter and dabs are evaluated per pixel along the path (Ciallo, SIGGRAPH 2024), never a stamp engine, so every frame = cold and sharp at any scale hold; a visible dab rhythm is optional and only for texture brushes. Research 2026-10-09 (tutorials, Wacom's and Clip Studio's guides, forums): professionals paint with 3 to 6 brushes; a hard round, a soft round, one textured brush and a tapered liner are the consensus core; square tips give the chiselled concept-art look; one brush per painting keeps it whole. Built-ins by job, about 10: Pencil (with tilt), Monoline, Inker, Hard Round, Soft Brush, Textured Round, Flat, Opaque Paint, Speckle; Smudge is the blender. Wet mixing (pick-up, drag, dilution) reads neighbours and comes after G6 (G8).

- S44 Taper and tilt is done (see "Done"): a taper stage whose end applies at the lift, tilt as a third factor of the dynamics, schema 19 (D71); Pencil with tilt, Inker, Monoline, Hard Round.
- S45 Shapes and scatter is done (see "Done"): stamps evaluated per pixel along the path (after Ciallo), each owned by one span, jittered by a hash of its index and the stroke's seed, four generated shape textures with a distance-field rim, schema 20 (D72); Textured Round, Flat, Opaque Paint, Speckle.
- S46 Brush editor is done (see "Done"): the chosen brush's row tapped again turns the panel into its editor in place, a live preview strip evaluated by the one evaluator, every engine setting within ranges that never let the engine refuse, copies and resets stored with the toolbox under owned keys, schema 21 (D73).
- S47 Brush sets is done (see "Done"): each picker opens on the chosen brush's set among five fixed ones (Recent, the last six brushes drawn with; Sketching, Inking, Painting, Texture, ordered by holding and dragging a row as layer rows are, `row_drag.rs` shared), the editor's Set row moves a brush to another set, stored with the toolbox, schema 22 (D74).
Exit: the author paints with the set on the tablet and judges each brush `pass` / `fail`. Passed 2026-10-09: "all good, very good, the preview included"; the agent choices of S43 to S47 accepted as they are. Finding: brushes with irregular textures get very laggy once much is painted or the pen moves fast; left to G7 by the author (S48).

## G7 Stability and release

Device tiers, long sessions, background/foreground, low storage, failed upgrades; GPU device-loss recovery and a VRAM budget; a device smoke scenario of at most 20 s; signed releases and a version policy. Optimisation happens here, coarse-grained, driven by measurements on the tablet; earlier slices build the simplest design that meets their budgets (D33) and leave performance ideas under "Candidates". Exit: the declared device matrix passes with no known artwork corruption or silent loss. The device matrix (author, 2026-10-09): the Wacom MovinkPad 14 alone, the only device the author uses; other devices are G8's multi-platform project.

- S48 Painting speed with many strokes is done (see "Done"): measured first (the GPU evaluating every finished op under the tail each frame, not the binning or the stamp loop), then the in-progress stroke resumes its layer from a float snapshot kept per tile and carried across commits (D75); frames over 600 Textured Round strokes cost about what they cost over none, the pen-down and the lift aside.
- S49 GPU robustness is done (see "Done"): every evaluation in dispatches bounded by a work estimate (about 100 ms on the tablet), the screen's canvas filling in over frames; a lost device made again from app state with the notice "The display was reset."; a GPU memory budget per device class dropping tiers, snapshots, the arena's unshown blocks and the layer pictures in that order (D76). The pen-down and lift scene rebuild stays a Candidate until the author feels it (decided 2026-10-11).
- S50 Storage and session robustness is done (see "Done"): every write one atomic fjall batch (tested by failing each write and cutting the journal at every byte), upgrades one artwork at a time with a broken one kept as it was and marked "Needs repair", the stroke being drawn committed when the app is left or its window goes, and an hour-long harness session measured (D77).
- S51 Memory over long sessions is done (see "Done"): measured first (a counting allocator in the harness, the store's and the canvas's structures by size, `meminfo` and `gpumem` on the tablet), the owner the numbers named was the smudge arena: residuals are now a cache held near what each evaluation evaluates, within a quarter of the GPU budget (D78); the driver's growth beside the app's memory is the author's decision (STATUS pending 9).
- S52 Smoke, versions, name and icon is done (see "Done"): `cargo device-smoke` walks the installed debug build through its main features on a test artwork it makes and deletes, told from the author's by the gallery's artwork ids; one version in the workspace manifest with the store's schema as build metadata, handed to Gradle by xtask and shown in Actions (D79); "OpenPaint" under an adaptive line-art icon.
- S53 Release build. Goal: a release build the author paints with daily. Waits on the author (STATUS pending): the author's library lives in the debug build (`dev.openpaint`, debug-signed, debuggable, which the device routines' `run-as` backups need); a release-signed build cannot update it in place, uninstalling would erase the library, and a release build cannot be backed up by `run-as`. Options: (a) a release build under its own id (`dev.openpaint.app`) beside the debug one, the author's artworks moved once through OpenPaint files (S36) and from then on never touched by agents, whose device routines keep to the debug app's own library; (b) stay on the debug build for daily use and make release builds only as files; (c) the release under `dev.openpaint` after a backup, uninstall and a restore through files. The signing key: created by the author or by the agent outside the repository, its backup the author's.

## G8 Independent extensions after stabilisation

Wet media, dual brushes, a brush ecosystem, animation, multi-platform, cloud sync, plugins: each is its own project and never enters the main line automatically.

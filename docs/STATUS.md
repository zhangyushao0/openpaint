## Working features

- The first screen: open the app, a dark top bar with "OpenPaint", then undo and redo arrows; below it a white canvas. Draw with the pen and a 12-pixel black round stroke follows the tip with pressure; lift and it stays. A finger draws nothing, by decision (D18: touch is reserved for gestures). One screen pixel is one canvas pixel.
- Undo and redo (S6): tap the arrows with a finger or the pen tip; each tap switches the artwork one version back or forward, the canvas updates in the same frame. An arrow with nothing left is dim grey and ignores taps; while the pen is drawing both are grey. A new stroke after undo drops what could be redone. A pen stroke that starts on the canvas stays a stroke when it lifts over the bar; a contact that starts on the bar never paints.
- Resume (S7): every finished stroke, undo and redo is saved in the background; nothing on screen changes. Leaving the app (`onPause`) saves what is left and waits up to 2 s. Opening the app shows the artwork saved last, pixel for pixel, at its own canvas size; history starts empty (it is not stored), so undo is grey after a restart. If a save fails, the right end of the top bar shows an alert icon, "Couldn't save. Your drawing is still here." and a Retry button (48-point text button); drawing goes on; the next stroke, a Retry tap or leaving the app tries again; a success removes the notice. If the library cannot be read, the app starts a blank artwork in a new project, leaves the old records untouched and shows "Couldn't open the last drawing. This is a new one." with OK.
- core: `Artwork` is an immutable value (`Arc` state: canvas, layers bottom to top, active layer, id counters, readable through `next_layer_id` / `next_stroke_id`); `apply(ArtworkCommand::Layer(..))` for create, delete, reorder, select, rename, visibility, opacity and lock; `StrokeSession` (begin, extend, finish, cancel); `to_parts` / `from_storage` with full validation; typed `CoreError`. Layer strokes are a chunked `StrokeList` (256 per chunk) shared between versions; `Artwork::bytes_since(base)`; `Stroke::shares_samples`. No dependencies.
- app: normalised input (`InputBatch`, `Contact`, `InputSample`); `Session { new, open, after_failed_open, dispatch, artwork, active, projection, history, save_request, leave_request, save_finished, saving }`. Intents: `Stroke(Contact)` (pen Down/Move/Up/Cancel), `History(Undo | Redo)`, `Storage(RetrySave | Dismiss)`; refusals are `AppError::Unavailable { action, availability }`. Projection: availability of `Undo`, `Redo`, `RetrySave`, `DismissNotice` (`Available`, `NothingLeft`, `StrokeInProgress`, `Running`) and `storage() -> StorageNotice`. History: versions costed by `bytes_since`, 64 MiB budget, newest step always kept (D20). Autosave: one save in flight; a failed version waits for a change, Retry or leaving (D21). Ports: `Project { id, artwork }`, `ProjectStore { open_last, create, save }`, `PortError { Device, Corrupt, NewerSchema, Invalid, Stopped }`.
- store: `Library::at(dir)` implements `ProjectStore` on fjall, opening the database on the first call and reopening after any failure. Schema 1 (D21): keyspace `library` (`last`, `next`), keyspace `projects` with a head record per project and one record per stroke; little-endian values with checked lengths; a save is one batch synced with `SyncData` that writes the head and the stroke records after each layer's common prefix with the version stored before; unknown base (after a failure, another instance) rewrites the project and removes stale records. Reading refuses truncated or trailing bytes, missing or misplaced stroke records (`Corrupt`), a newer schema (`NewerSchema`) and rule breaks (`Invalid`).
- render, devices: `Core::headless()`, `Core::create_surface`, `render_clear`, `wait_idle`; FNV-1a 64 `content_hash` on readbacks.
- render, evaluation: `RegionEvaluator::new(&core, &mut target).evaluate(&FrameRequest { artwork, active, background }, &[PixelRect])` is the single entry; the target keeps the in-progress stroke's coverage and the last scene's ops (D16, D17); `changed_regions(before, after)` for version switches. Tapered capsules, one-pixel antialiasing, coverage union, layer opacity, hidden layers skipped, 16 px tile binning, protocol generated into WGSL.
- render, screen: `ScreenPainter` draws `ScreenFrame { surround, canvas, ui }` in one pass into a window (`present`) or a `ScreenTarget` (`render_screen`).
- ui: theme in `design` (chrome grey 38, text 222, disabled 92, pressed 64, text-button face `RAISED` 52, surround 24, 8-point spacing, 48-point targets, one type scale); icons Undo, Redo, Alert (own line drawings). Components: `top_bar`, `icon_button`, `text_button`, `notice` (alert icon, message and one action at the right end of the bar; it never covers or moves the canvas), `canvas_frame` with `CanvasInput`. `Shell { show, canvas_area, route }`.
- runtime: `Runtime::start(density, Box<dyn ProjectStore>)` starts the storage worker (`worker::Latest`, the only place a thread starts; the store runs on it, panics become `PortError::Stopped`) and asks it to open the last project; `attach`, `resize`, `detach`, `leave`, `motion`, `frame`, `projection`, `storing`, and for the harness `frame_offscreen`, `read_offscreen`, `read_canvas`, `screenshot`, `wait_idle`, `artwork`, `adapter`. A frame: storage results -> input -> egui from the projection -> route -> dispatch -> evaluate -> hand an unsaved version to the worker -> draw. Frames keep coming while the library opens and while a save runs. The canvas opens once the library answered and the canvas area is known: the stored artwork, or a blank one of the area's size. Dropping the runtime finishes the save still waiting.
- android: Kotlin `MainActivity` passes `getFilesDir()` to `Native.create` (library in `files/library`) and calls `Native.leave` in `onPause`; full-screen `SurfaceView`, `Choreographer` pacing, system bars hidden on API 30+, rotation through `configChanges`, `MotionEvent`s as primitive arrays. JNI errors and panics are logged under tag `openpaint`.
- harness: `render-smoke`, `render-stroke`, `shell-smoke`, `replay` (each command starts on an emptied library under `artifacts/harness/<name>-library`); `replay`: 10,000-sample pen scribble and a finger swipe at 2880 x 1800, density 1.75, then 20 tapped undo/redo round trips; canvas = cold evaluation, golden `1f94cbfbd4b11e02`, slowest frame against 8 ms. Run with `cargo run --release -p openpaint-harness -- replay`.
- devtools and scenarios: `tests/scenarios/<name>.json` = walk-through, `screen`, `density`, `steps`: `tap`, `drag`, `stroke`, `wait`, `restart` (leave, drop the runtime, start again on the same library), `storage_fails` / `storage_works` (the runner's store wrapper fails every call while off), `checkpoint`, `screenshot`. `openpaint_devtools::run(&scenario, library_dir)`; after each step it runs frames until the storage worker is idle. Typed `ScenarioError` for unknown steps, bad hashes, empty strokes, reused names.
- `cargo scenario <name>` empties `artifacts/scenarios/<name>/library/`, runs, writes screenshots, passing canvases and failure diffs (D19). Scenarios: `smoke` (`2c6751195ed1a7ae`), `s4-first-stroke` (`ee6a94bf9052c12f`), `s6-history` (7 checkpoints), `s7-resume` (2880 x 1800 at 1.75; undo at window pixel (230, 42), Retry at (2789, 42): two strokes `89059432dd1fda18` before and after restart; a third stroke undone then restart `89059432dd1fda18`; a stroke drawn while storage fails stays `bab6206485558079`, Retry while failing keeps the notice, Retry after recovery clears it, restart `bab6206485558079`; a stroke drawn while failing, storage recovers, restart without Retry `8504fa0aadaeaef0`).

## Known limits

- History and editor state are not stored; a restart starts with an empty history. There is no editor state yet (the brush is fixed).
- One project only: the library holds every project ever created, but the app opens the last one and has no gallery until S10. A project that failed to open stays in the library unreachable until then.
- A save rewrites the head (layer table and stroke counts) every time and compares each layer's strokes by pointer from the start (O(strokes) pointer checks on the worker); bytes written are the changed strokes only.
- `leave` waits at most 2 s on the main thread; a longer save continues in the background and is lost if the system kills the process first. A stroke still being drawn when the app is left is not saved.
- Storage failure on the tablet was not provoked (only on the dev machine through the scenario's store switch). The notice text does not distinguish a full disk from other errors; the reason is in the log.
- fjall and lsm-tree log keyspace recovery at info level under the `openpaint` tag on Android.
- GPU tests fail (not skip) on a machine without any adapter; CI relies on software Vulkan.
- Golden hashes are verified on one desktop GPU (Vulkan and DX12); software and mobile adapters are unverified. Only canvas pixels are golden.
- The finished strokes still cost per frame: each evaluation bins every finished op of the scene on the CPU.
- Vulkan on the dev machine: a ~1.5 ms CPU stall every ~4,000 `write_buffer` calls; DX12 shows none. Not measured on the tablet.
- No view transform: one screen pixel is one canvas pixel. A new canvas takes the size of the canvas area on the first frame; a stored canvas keeps its size, so after rotation part of it is off screen.
- The brush is fixed (12 px, black, opacity 1) until S11. Pressure maps linearly to the diameter; tilt and azimuth are stored, not used. Blending is in sRGB-encoded values.
- egui gets pointer events from the first contact of each batch only; no multi-touch gestures. A button that became enabled takes a press only after one frame has laid it out enabled.
- `changed_regions` redraws the whole canvas for any layer property change. History holds strokes only (no layer intents yet).
- Frames and input run on the Android main thread; a slow frame delays input delivery.
- The screen painter is created with the first target's format; a later surface with another format fails with `RenderError::Invalid`.
- On API 28 and 29 the navigation bar stays visible.
- The Gradle and Kotlin daemons outlive `cargo android-build` and hold its output handles: redirect its output to a file.
- No emulator image on the dev machine; Android behaviour is checked over adb on the tablet.
- Scenarios: one pointer per gesture; samples carry no tilt or orientation; button positions are window pixels that move if the bar's layout changes; a failed checkpoint gets a diff only if it passed before on this machine (D19). Screenshots are never compared.

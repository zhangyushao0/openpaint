## Working features

- The first screen: open the app, a dark top bar labelled "OpenPaint", below it a white canvas. Draw with the pen and a 12-pixel black round stroke follows the tip with pressure; lift and it stays. A finger draws nothing, by decision (D18: touch is reserved for gestures). One screen pixel is one canvas pixel.
- core: `Artwork` is an immutable value (`Arc` state: canvas, layers bottom to top, active layer, id counters); `Artwork::new(canvas)` starts with "Layer 1". `apply(ArtworkCommand::Layer(..))` returns `Applied { artwork, change }` for create, delete, reorder, select, rename, visibility, opacity and lock; `StrokeSession` (begin on the active layer, extend all-or-nothing, finish as one version, cancel to the base); `to_parts` / `from_storage` with full validation; typed `CoreError`. Layer strokes are a chunked `StrokeList` (256 per chunk, `last()` is O(1)) shared between versions. No dependencies.
- app: `InputBatch { contacts }`, `Contact { id, device, phase, samples }` (devices Pen, Eraser, Finger, Mouse, Unknown; phases Hover, Leave, Down, Move, Up, Cancel), `InputSample { position, pressure, tilt, azimuth, time_ms }`. `Session::new(canvas)` holds the artwork and the stroke intent; `dispatch(Intent::Stroke(StrokeIntent::Contact(..)))`: a pen Down begins a stroke (12 px, opacity 1, black), Move extends it, Up extends and commits, Cancel drops it; other devices and other contact ids are ignored; a Down while a stroke is open commits that stroke first. Sample times count from the stroke's first sample. `artwork()` is the version being drawn over, `active()` the stroke beside it. Typed `AppError`.
- render, devices: `Core::headless()` opens a wgpu device without a window and builds the evaluator and blit pipelines; windows attach through `Core::create_surface(window, size)` (Fifo, first non-sRGB format). `Core::render_clear` clears and reads back an `RgbaImage` with an FNV-1a 64 `content_hash`; `Core::wait_idle` blocks until the GPU is done.
- render, evaluation: `RegionEvaluator::new(&core, &mut target).evaluate(&FrameRequest { artwork, active, background }, &[PixelRect])` is the single entry. `CanvasTarget` (an `Rgba8Unorm` canvas texture) keeps its pixels, an `R32Float` coverage texture for the in-progress stroke, the last scene's ops on the GPU (rebuilt only when the artwork version or active layer changes) and its buffers and bind groups (rewritten in place). Each evaluation adds only the stroke's new segments to its kept coverage (`EndActive` op, maximum is exact) and evaluates only the tiles they reach; it erases a stroke dropped while the artwork kept its version and draws the samples a committed stroke gained since its last evaluation. Callers pass regions only for other artwork changes. Strokes are tapered capsules with one-pixel antialiasing, coverage union, one opacity; layers composite with opacity; hidden layers are skipped. Ops are binned into 16 px tiles; opcodes and records are generated into WGSL from `protocol.rs` (DECISIONS D16, D17).
- render, screen: `ScreenPainter` (in `adapter/`) draws a `ScreenFrame { surround, canvas: Option<CanvasPlacement { target, origin }>, ui }`: clear to the surround, blit the canvas unfiltered at its origin through the viewport, egui over it, one pass. `Core::present` draws into a window; `Core::render_screen` into a `ScreenTarget` (offscreen, read back on demand).
- ui: `design::install(ctx)` sets the theme once: chrome grey 38, text grey 222, surround grey 24 (`SURROUND`), 8-point spacing (`SPACE`), 48-point touch targets (`TOUCH_TARGET`), one type scale (12/16/16/20/14). `components::top_bar` (48 points, chrome fill, 16-point side margin) and `components::canvas_frame` (the rest of the screen, unpainted) with `CanvasInput`, which owns each contact that touches down inside the canvas area until it lifts or cancels and moves it into canvas pixels. `Shell { show(ui), canvas_area(), route(batches) -> Vec<Intent> }`; routing runs after the egui pass, never twice.
- runtime: `Runtime` frame loop from one thread: `start(density)` (installs the theme), `attach`, `resize`, `detach`, `motion(&MotionBatch) -> wants a frame`, `frame()`, and for the harness `frame_offscreen(size)`, `read_offscreen()`, `read_canvas()`, `screenshot(size)`, `wait_idle()`, `artwork()`, `adapter()`. A frame: pending input -> egui (pointer events from the first contact of each batch) -> route contacts -> dispatch intents (refusals logged) -> evaluate -> draw. The normaliser turns `MotionBatch`es into `InputBatch`es: per-pointer phase (pointer down/up by index), pressure clamped to 0..1, tilt to 0..pi/2, orientation wrapped into -pi..pi as azimuth, non-finite positions dropped, times never decreasing within a contact, button-only events dropped. The first frame that knows the canvas area opens a blank artwork of that size; later rotations move it, never resize it.
- android: Kotlin `MainActivity` owns a full-screen `SurfaceView`, paces frames with `Choreographer`, hides system bars on API 30+, handles rotation through `configChanges`, forwards every `MotionEvent` as primitive arrays decoded in `motion.rs`, and asks for a frame when `Native.motion` says the event needs one. JNI errors and panics are logged under tag `openpaint`; per-batch input lines are now debug level.
- harness: `render-smoke` (`smoke.png`, `261e692a5ece1106`), `render-stroke` (`stroke.png`, `ba8523102ad38e3a`), `shell-smoke` (`shell.png`, 2560 x 1600 at density 2), `replay`: a 10,000-sample pen scribble (4 samples per batch, 4 ms apart) and a 120-sample finger swipe through the full frame loop at 2880 x 1800, density 1.75; times each frame until the GPU is done, checks the canvas against a cold evaluation and the golden hash, the slowest frame against 8 ms; writes `artifacts/harness/replay.png` (screen) and `replay-canvas.png` (canvas, golden `1f94cbfbd4b11e02`). Run it with `cargo run --release -p openpaint-harness -- replay`.
- devtools and scenarios: `tests/scenarios/<name>.json` = walk-through text, `screen`, `density`, `steps`. Steps: `tap { at, tool }`, `drag { from, to, tool }` (tool `finger` by default, `stylus`), `stroke { points: [[x, y, pressure], ..] }` (pen), `wait { frames }`, `restart`, `checkpoint { name, canvas: "<16 hex>" }`, `screenshot { name }`. Positions are window pixels. Unknown steps or fields, bad hashes, empty strokes and reused or non-plain names are refused with a typed `ScenarioError` (JSON errors carry line and column). `openpaint_devtools::run` replays each gesture as one `MotionBatch` per frame (samples 4 ms and at most 4 px apart, 4 per batch) through `Runtime` offscreen and returns a `Report` (checkpoints with the canvas, screenshots, frames, time). `restart` drops the runtime and starts a new one: nothing survives until storage exists (S7).
- `cargo scenario <name>` runs a scenario and writes under `artifacts/scenarios/<name>/`: `<screenshot>.png`; `<checkpoint>.canvas.png` on each pass (the diff reference, D19); on a failure `<checkpoint>.actual.png` and `<checkpoint>.diff.png` (differing pixels red over a faded canvas, against the last passing canvas), paths printed, exit code 1. Scenarios: `smoke` (640 x 400 at density 2, one pen line, canvas `2c6751195ed1a7ae`) and `s4-first-stroke` (2880 x 1800 at 1.75: pen curve, then a finger drag, a finger tap and a wait leave the canvas at the same hash `ee6a94bf9052c12f`).
- Build: `cargo android-build` (cargo-ndk arm64-v8a API 28 release, Gradle 8.13 wrapper jar, AGP 8.13.2, Kotlin 2.2.21, SDK 35); `cargo android-install` also installs and starts the activity.
- Gate steps: fmt, clippy, clippy-android (`aarch64-linux-android`; needs the rustup target, not the NDK), test, scenario smoke (debug build), repo-check.
- Pinned (D14): wgpu 30.0.1, egui 0.36.2, egui-wgpu 0.36.2, pollster 1.0.1, png 0.18.1, serde 1.0.229, serde_json 1.0.151, jni 0.22.4, log 0.4.34, android_logger 0.15.1, raw-window-handle 0.6.2. No windowing crate in the graph.

## Known limits

- GPU tests fail (not skip) on a machine without any adapter; CI relies on software Vulkan.
- Golden hashes are verified on one desktop GPU (Vulkan and DX12); software and mobile adapters are unverified. The screen image (egui text) differs between Vulkan and DX12; only canvas pixels are golden.
- The finished strokes still cost per frame: each evaluation bins every finished op of the scene on the CPU, and each pixel of a re-evaluated tile walks every finished op that reaches it. The in-progress stroke costs only its new samples.
- Vulkan on the dev machine: a ~1.5 ms CPU stall every ~4,000 `write_buffer` calls (about every 512 frames), from wgpu's staging memory; DX12 shows none. Not measured on the tablet.
- No view transform: one screen pixel is one canvas pixel. The canvas takes the size of the canvas area on the first frame (portrait or landscape, whichever the app starts in); after rotation part of it is off screen and the rest of the screen shows the surround.
- The brush is fixed (12 px, black, opacity 1) until brush settings (S11). Pressure maps linearly to the diameter; a pressure of 0 draws nothing; tilt and azimuth are stored, not used. Blending is in sRGB-encoded values.
- egui gets pointer events from the first contact of each batch only; no multi-touch gestures. The top bar has no buttons yet.
- Frames and input run on the Android main thread; a slow frame delays input delivery. Event times are milliseconds (`getEventTime`).
- The screen painter is created with the first target's format; a later surface with another format fails with `RenderError::Invalid` (not seen on any device).
- On API 28 and 29 the navigation bar stays visible (the system-bar hiding needs API 30).
- The Gradle and Kotlin daemons outlive `cargo android-build` and hold its output handles: redirect its output to a file instead of piping.
- No emulator image on the dev machine; Android behaviour is checked over adb on the tablet. The harness renders offscreen only.
- core: a stroke style is size, opacity and an opaque sRGB colour only (recipes in S11); layer lock blocks strokes only; drawing on a hidden layer is allowed (and invisible).
- Scenarios: one pointer per gesture (no multi-touch steps yet); samples carry no tilt or orientation; `restart` keeps nothing until S7. A failed checkpoint gets a diff only if it passed before on this machine (references are untracked, D19); on a fresh clone only the actual canvas is written. Screenshots are never compared.
